02_模拟Qwen本地调用 - 代码讲解

位置：AI Agent Development Code/aiTest/char03 | 教学主题：本地部署 vs 云端调用两种推理形态 | 技术栈：原 transformers/torch 本地推理 → 改写为 dashscope 云端调用 | 已验证可运行（5 个成语批量云端推理全部成功）

一、这段代码要做什么

原教材演示的是本地部署大模型的完整五步流程：装依赖 → 下载模型权重到显卡 → 构造提示词 → 本地执行推理（逐 token 生成）→ 批量测试。因为 Qwen-235B 这种规模的模型需要数百 GB 显存的专业多卡环境，普通电脑装不下也跑不动，所以按用户要求把"模型加载"部分替换为百炼云端调用——模型权重留在云上，本地只发 HTTP 请求。而提示词构造、推理参数（max_tokens / temperature）、批量测试循环原样保留。

本篇真正的教学价值：一次看懂两种推理形态

改写后的文件里同时存在两套代码（原版注释保留）：一套本地推理（transformers），一套云端推理（dashscope）。两套代码做的是同一件事——输入提示词、输出文本——对比它们，就理解了大模型行业"私有化部署"和"API 调用"两条路线的本质区别。

二、原教材代码的问题与改写思路

问题不是"写错了"，而是"跑不起来"
  • 资源门槛：Qwen-235B 是 2350 亿参数规模的模型，float16 加载需要约 470GB 显存——没有 8 卡 A100/H100 集群根本无法加载，普通开发机必然 OOM
  • 依赖门槛：torch + transformers + accelerate 全家桶数 GB 下载量；pip install qwen==1.0.3 这个包在真实环境也并非教材所述形态
  • 模型名问题：HuggingFace 上没有 "Qwen/Qwen-235B" 这个公开仓库（真实 Qwen 系列是 Qwen2.5、Qwen3 等），from_pretrained 会直接报仓库不存在

改写原则：本地部署代码全部注释保留（它是理解推理原理的好教材），运行部分换成百炼云端调用；build_prompt、参数语义、批量循环原样保留。

四、本地五步 → 云端改写的逐项映射

原版步骤（本地部署）改写版对应（云端调用）变化说明
① pip install torch / transformers / accelerate（数 GB 依赖）只需已安装的 dashscope 包依赖从"深度学习全家桶"缩到"一个 HTTP SDK"
② AutoTokenizer.from_pretrained("Qwen/Qwen-235B") 下载分词器不需要——分词在云端完成本地不再接触 token 化细节
② AutoModelForCausalLM.from_pretrained(device_map="auto", torch_dtype=float16) 加载权重dashscope.api_key = os.environ.get('DASHSCOPE_API_KEY')"加载模型"变成了"配置钥匙"——这是两种形态最本质的差异
③ build_prompt() 构造提示词原样保留，一字未改提示词工程与部署形态无关
④ model.generate(**inputs, max_new_tokens=128, do_sample=True, temperature=0.7) 本地逐 token 生成dashscope.Generation.call(model='qwen-plus', max_tokens=128, temperature=0.7)参数几乎同名同义：max_new_tokens→max_tokens；do_sample=True 对应云端默认采样模式
④ tokenizer.decode(outputs[0], skip_special_tokens=True) 解码response.output.choices[0].message.content解码也在云端完成，本地直接拿文本
⑤ for 循环批量测试 5 个成语原样保留，一字未改业务逻辑与部署形态无关

五、逐段讲解（3 个代码块）

块 1：本地部署部分（注释保留，但要读懂它）

tokenizer = AutoTokenizer.from_pretrained("Qwen/Qwen-235B", trust_remote_code=True)
model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen-235B",
    device_map="auto",           # accelerate 库的能力：自动把层分配到 GPU/CPU
    torch_dtype=torch.float16,   # 半精度：显存占用减半（470GB→235GB，仍然巨大）
    trust_remote_code=True       # 允许执行模型仓库自带的自定义代码
)
model.eval()                     # 推理模式：关闭 dropout 等训练专用行为

def run_inference(prompt, max_tokens=128, temperature=0.7):
    inputs = tokenizer(prompt, return_tensors="pt").to(model.device)  # 文本→token张量
    with torch.no_grad():        # 推理不需要梯度，省内存提速
        outputs = model.generate(**inputs, max_new_tokens=128,
                                 do_sample=True, temperature=0.7)  # 逐token生成
    return tokenizer.decode(outputs[0], skip_special_tokens=True)  # token→文本
这段"跑不起来"的代码为什么值得保留

它揭示了云 API 帮你藏掉了什么：分词、张量设备搬运、无梯度上下文、逐 token 循环生成、解码——这五件事云端服务全包了。理解它们，你才能看懂"大模型推理服务"（vLLM、Ollama 等本地部署工具）到底在做什么；面试里"本地部署和 API 调用的区别"也考这些。

块 2：云端改写版 run_inference（本篇的运行主体）

def run_inference(prompt: str, max_tokens: int = 128, temperature: float = 0.7):
    try:
        response = dashscope.Generation.call(
            model='qwen-plus',
            messages=[{"role": "user", "content": prompt}],
            max_tokens=max_tokens,       # 与原 max_new_tokens 语义一致
            temperature=temperature,     # 与原 generate 的 temperature 语义一致
            result_format='message'
        )
        return response.output.choices[0].message.content.strip()
    except Exception as e:
        return f"调用失败: {str(e)}"    # 永不抛异常，批量任务不因单条失败而中断

注意函数签名和原版完全一样（prompt / max_tokens / temperature 三个参数）——这是改写的刻意设计：上层业务代码零改动，只换底层实现。这就是接口抽象的价值。

块 3：批量测试循环（原样保留）

idioms = ["画蛇添足", "纸上谈兵", "掩耳盗铃", "望梅止渴", "指鹿为马"]
for idiom in idioms:
    prompt = build_prompt(idiom)
    result = run_inference(prompt)
    print(f"\n【{idiom}】\n{result.strip()}\n")

每条解释都在 200 字左右戛然而止（句子说到一半就断了），因为默认参数 max_tokens=128 限制了回复长度——128 个 token 约合 100-200 个汉字。这不是 bug，是参数生效的表现。想看完整解释，把调用改成 run_inference(prompt, max_tokens=800) 即可。这比讲十遍"max_tokens 是什么"都直观。

七、什么时候本地部署，什么时候云端调用

维度本地部署（原版路线）云端调用（改写版路线）
硬件门槛极高：7B 模型约需 16GB 显存，235B 需多卡集群零：能上网的电脑即可
数据隐私数据不出门——金融/医疗/政务敏感场景的首选数据上传第三方平台
成本结构一次性硬件投入 + 电费 + 运维人力，用得越多越划算按 token 计费，零用量零成本，量大后成本线性上涨
弹性扩容 = 买卡装机，周期以月计换模型名即切换，秒级
延迟与离线内网低延迟，可完全离线依赖网络，公网往返几十到几百毫秒
典型选择者大厂、国企、数据合规要求严的行业初创团队、个人开发者、快速验证阶段
本课程的选择逻辑

教学和原型阶段一律走云端（百炼）——把算力难题交给平台，学习焦点放在提示词、Agent 架构和应用逻辑上。等业务真正需要私有化时，你已经在注释里见过完整的本地部署代码形态，迁移时知道要补什么课。

八、教学简化 vs 生产差距

  • 真实本地部署的工具链：生产级本地推理不用裸 transformers，而用 vLLM（吞吐量高、支持连续批处理）或 Ollama / llama.cpp（消费级显卡跑量化小模型）——原版代码是"原理教学版"而非"部署实操版"
  • 云端调用缺并发与重试：5 条串行调用，无 429 限流处理（同 char03-01）
  • 模型名与参数写死：qwen-plus / 128 / 0.7 应进配置；量化版本地部署时参数体系（quantization_bits、gpu_memory_utilization）会更复杂
  • 无输出持久化：结果 print 完即丢，应落 JSON/数据库

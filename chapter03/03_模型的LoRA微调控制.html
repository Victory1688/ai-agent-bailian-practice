位置：AI Agent Development Code/aiTest/char03 | 教学主题：LoRA 微调的云端工程化路径 | 技术栈：本地 PEFT LoRA 原理（注释保留）→ 改写为百炼 FineTunes + Files API | 已验证可运行（上传成功，提交返回 403 为百炼权限限制）

一、这段代码要做什么

原教材演示的是本地 LoRA 微调的完整 9 步流程——加载基座模型 → 配置 LoRA 注入位置 → 构造数据集 → Trainer 训练 → 保存权重。因为 LoRA 训练也需要本地显卡（至少 16GB 显存 + CUDA 环境），普通电脑跑不动，所以按用户要求把"本地训练"替换为百炼云端微调提交。LoRA 原理代码全部注释保留（理解微调机制的好教材），运行部分换成百炼 FineTunes API 的三步：构造 JSONL → 上传 → 提交。

LoRA 微调：大模型应用开发的"定制化"环节

前两篇 char03 代码教了"怎么调大模型推理"，本篇教"怎么把大模型改成更懂你业务的定制版本"。LoRA（Low-Rank Adaptation）是当前最主流的微调方式——它冻结基座模型 99.9% 的参数，只在注意力层的 q_proj / v_proj 上注入极小的低秩矩阵做增量训练。产出权重通常只有几 KB 到几 MB，可以像"插件"一样随时挂载/卸载/分享。

二、LoRA 核心概念速查（新人请先看懂再看代码）

概念一句话解释代码中的对应
基座模型被微调的原始大模型（如 Qwen-1.8B / qwen-plus）本地 AutoModelForCausalLM.from_pretrained；云端 FineTunes.call(model='qwen-plus')
LoRA 注入在基座模型的特定权重矩阵上挂一个小的增量矩阵 ΔW = BA本地 get_peft_model(base_model, lora_config)
r（LoRA 秩）低秩矩阵的宽度。r 越小参数越少、训练越快；越大表达能力越强本地 LoraConfig(r=8)；云端 hyper_parameters["lora_r"]=8
target_modules在哪些权重上注入 LoRA（q_proj / v_proj / k_proj / o_proj 可选）本地 target_modules=["q_proj", "v_proj"]；云端 LoRA 模式默认注入注意力层
LoRA 权重训练后产出的小权重文件（adapter_model.safetensors），只有基座模型的 0.01% 大小本地 model.save_pretrained("./output/...")；云端训练完成后在百炼控制台下载
指令微调（SFT）用"问题-答案"对训练，让模型学会你想要的回答风格/领域知识本地 preprocess() 把 text+label 拼成 prompt；云端 messages 格式数据

五、逐段讲解（4 个代码块）

块 1：build_training_data —— 数据格式适配

# 原代码格式（本地 datasets 库用）：
# data_dict = {"text": ["客服态度很好...", ...], "label": ["正面", ...]}

# 改写后格式（百炼微调要求 JSONL + messages）：
def build_training_data():
    samples = [("客服态度很好...", "正面"), ("屏幕亮度太低...", "负面"), ...]
    lines = []
    for text, label in samples:
        item = {
            "messages": [
                {"role": "user", "content": f"请判断以下句子的情感倾向：{text}"},
                {"role": "assistant", "content": label}
            ]
        }
        lines.append(json.dumps(item, ensure_ascii=False))
    return "\n".join(lines)      # 每行一条 JSON = 百炼要求的 JSONL 格式
两种数据格式的本质区别

本地版是"标签式数据集"（输入文本 + 标签），需要自己 preprocess 拼成 prompt 再 tokenize；百炼版是"指令微调格式"（messages 数组），模型自动识别 user → assistant 的监督学习模式。格式更接近 Chat 模型的原生交互方式。

块 2：upload_dataset —— 上传到百炼

def upload_dataset(jsonl_content: str, file_name: str = "lora_sentiment_train.jsonl") -> str:
    temp_path = os.path.join(..., file_name)        # 1. 写成临时文件
    with open(temp_path, "w", encoding="utf-8") as f:
        f.write(jsonl_content)
    resp = Files.upload(file_path=temp_path, purpose='fine_tune')   # 2. 上传
    os.remove(temp_path)                              # 3. 删临时文件
    if resp.status_code == 200:
        return resp.output['uploaded_files'][0]['file_id']        # 4. 拿到 file_id
    return None

块 3：submit_lora_finetune —— 提交 LoRA 微调任务（改写的核心）

def submit_lora_finetune(file_id: str, model: str = "qwen-plus"):
    hyper_params = {
        "lora_r": 8,                  # ← 本地 lora_config.r
        "lora_alpha": 16,             # ← 本地 lora_config.lora_alpha
        "lora_dropout": 0.1,          # ← 本地 lora_config.lora_dropout
        "learning_rate": 3e-4,        # ← 本地 train_args.learning_rate
        "epoch_count": 3,             # ← 本地 train_args.num_train_epochs
        "batch_size": 2,              # ← 本地 train_args.per_device_train_batch_size
    }
    resp = FineTunes.call(
        model=model,                  # 基座模型
        training_file_ids=[file_id],  # Step 2 上传得到的文件 ID
        mode="lora",                  # ← 本地 TaskType.CAUSAL_LM
        hyper_parameters=hyper_params
    )
    # resp.status_code == 200 → 提交成功，返回 fine_tune_id
    # resp.status_code == 403 + code="Model.AccessDenied" → 账号无微调权限

注意——LoRA 微调是异步长任务：提交后返回 fine_tune_id，训练在云端 GPU 集群进行（几十分钟到几小时），期间可以用 FineTunes.wait(fine_tune_id) 阻塞等待或用 FineTunes.get(fine_tune_id) 查询状态。训练完成后在百炼控制台下载 LoRA 权重文件。

块 4：本地 LoRA 原理代码（注释保留，必懂）

# 1. 加载基座模型（Qwen-1.8B，float16 约 3.6GB）
base_model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen-1.8B", device_map="auto", torch_dtype=torch.float16)

# 2. 配置 LoRA：r=8 意味着注入 8 维的低秩矩阵
lora_config = LoraConfig(task_type=TaskType.CAUSAL_LM, r=8,
    lora_alpha=16, lora_dropout=0.1, target_modules=["q_proj", "v_proj"])

# 3. 注入：get_peft_model 把基座模型 + LoRA 适配器组装成可训练模型
model = get_peft_model(base_model, lora_config)

# 4. 训练：Trainer 是 transformers 的高级训练封装（自动处理梯度、优化器、日志）
trainer = Trainer(model=model, args=train_args, train_dataset=tokenized_dataset)
trainer.train()

# 5. 保存：只保存 LoRA 权重（几 KB），基座模型不动
model.save_pretrained("./output/qwen_lora_sentiment")

403 不是代码 bug，是平台权限限制

百炼平台对 LoRA 微调有账号权限控制——个人账号默认未开通微调功能，需要在百炼控制台申请。上传数据（Files.upload）是公开接口所以能成功，但提交训练（FineTunes.call）需要微调权限。代码逻辑和 API 调用完全正确，有权限的账号提交后会返回 200 + fine_tune_id，训练完成后可以下载 LoRA 权重挂载到推理时使用。

七、LoRA 微调完整闭环（提交后发生了什么）

FineTunes.call(mode="lora", model="qwen-plus", hyper_parameters={...})
  │
  │ 返回 fine_tune_id + status=200
  ▼
百炼云端 GPU 集群（异步训练，几十分钟到几小时）
  │
  ├─ 1. 从基座权重加载 qwen-plus
  ├─ 2. 在注意力层 q_proj / v_proj 上注入 LoRA (r=8)
  ├─ 3. 加载你的 6 条 JSONL 数据
  ├─ 4. 按 epoch_count=3 训练
  │     每个 epoch: 前向 → 计算 loss → 反向传播只更新 LoRA 参数 → 优化器 step

  │
  ▼
训练完成后：
  │
  ├─ 百炼控制台: 直接下载 LoRA 权重 zip
  ├─ API: FineTunes.get(fine_tune_id) 查询 status="SUCCEEDED" 后获取下载地址
  │
  ▼
推理时挂载 LoRA：

八、教学简化 vs 生产差距

  • 数据集太小：6 条样本是教学极简集，生产 LoRA 微调通常需要数千到数万高质量样本（指令微调 SFT 更是如此）。6 条在云端也能跑通训练，但模型不会真的学到东西——只是演示流程
  • 单模态微调：只演示了 CausalLM 指令微调。LoRA 也可以微调 Embedding、Rerank、多模态模型，但百炼 API 会有不同的 mode 和 hyper_parameters
  • 无评估集与验证：生产应拆 train/val，每个 epoch 后在 val 集上跑指标（准确率、F1），防止过拟合。百炼 FineTunes.call 支持 validation_file_ids 传入验证集
  • 未演示 QLoRA：原版代码是标准 LoRA（fp16/fp32 基座），显存需求仍不小。QLoRA 用 4-bit 量化基座 + LoRA，显存几乎砍半，百炼 mode="qlora" 支持
  • 训练后效果对比未自动化：生产应写自动化评测脚本——同一批样本跑 base vs LoRA，输出准确率差、典型错误、分领域变化

九、动手练习

  1. 申请权限 + 跑通提交：在百炼控制台申请微调权限，或换一个支持微调的模型（部分模型对已认证用户开放），让 FineTunes.call 返回 200 + fine_tune_id。这是完整闭环的第一步。
  2. 扩展数据集：把样本扩展到 20-50 条，覆盖正面/负面/中性、不同品类（手机/食品/服务），重新上传提交——观察训练时间是否明显变长。
  3. 调 LoRA 秩：分别用 r=4 / r=16 / r=64 跑三次微调（在同一份数据上），训练完成后对比三者的"正面情感分类"准确率差异——理解 r 如何影响 LoRA 的表达能力。
  4. 思维题：你要做一个"中医术语自动翻译"工具，基座模型是通用大模型。用 LoRA 微调 vs 用 RAG（检索增强生成）vs 用 Few-Shot Prompting，你会选哪种？列出三条理由。
  5. 进阶（本地版）：如果有 16GB+ 显存显卡，用 Ollama 拉 Qwen2.5-1.5B，用 PEFT + peft-train 脚本跑本地 LoRA 微调——对比云端和本地的训练时间、显存占用、调参便捷性。

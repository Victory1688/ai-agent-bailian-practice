二、这组代码想表达什么：从"链"到"图"的编排升级

char05 想表达的是大模型应用编排方式的跃迁——用显式有向图取代线性链和黑盒循环。char04 的 SequentialChain/initialize_agent 各自只有一种形状（线性流水线 / 框架黑盒），LangGraph 把执行流变成"看得见、改得动"的图：

编排形态代表能力边界
手写顺序调用char01单向一问一答，无循环无分支
手写循环char02（agent_chat while True）有循环，但流程硬编码在代码里
框架黑盒char04（initialize_agent）有循环有决策，但内部不可见不可控
显式图（本篇）char05（LangGraph）节点是普通函数、边是显式声明——顺序/条件/并行/循环四种形状全部可声明，既看得见又改得动

四、系列级教学财富：char05 独有的四笔"学费清单"

1. 十连坑：State(Dict) 静默失败的完整谱系
形态篇现象危险度
裸 dict 子类01-08invoke 返回 None（错在出口，一眼见尸）高（不报错）
TypedDict 漏字段09图正常跑完，不在 schema 里的输入键被静默裁剪（错在入口，结果"看起来正常"）更高
修复姿势全部TypedDict 字段 = 节点要读写的全部键（含入口键 query）—
2. 降级链三部曲（05-07）：字符串失败信号的可靠性问题

05 信号整体替换（链活）→ 06 信号被格式加工（链断）→ 07 信号被加工函数放行（链活，纯靠运气：信号里恰好没有会被 replace 命中的字）。结论：失败状态是元信息，别和正常数据混管道靠字符串比对——生产用结构化 status 字段。

3. 教材输出问题谱系（char05 是重灾区）

05 手写估算截断位置（少算一字）→ 07 首次全对 → 08/09 正确 → 10 键名造假顶点（AgentD_results 键不存在 + 展示随机分工"最好看的一种可能"）。方法论沉淀：教材输出永远以实测为准，尤其是含随机性的示例。

4. 协议名陷阱连续剧（08-09）

08 的"MCPInterface"与真实 MCP 协议（Anthropic）无关、09 的"A2AProtocol"与真实 A2A 协议（Google，MCP 的姊妹协议）无关——教材借热门名词做教学命名。见到"自定义 MCP/A2A 类"先做同名辨析；真实集成走 langchain-mcp-adapters。

五、char05 贯穿十篇的三条不变式

  • ① 节点 = 纯函数（状态进，部分更新出）：入参是整个 State（只读视角），返回值是要合并的增量字典——十篇全部如此，比 SequentialChain 的变量名接线更自由，也比黑盒 Agent 更可控
  • ② 图结构 = 显式声明（add_node + add_edge + set_entry_point）：执行流不在代码逻辑里而在图定义里——改流程 = 改声明，不动节点函数（05→06→07 三次换实现骨架零改动的实证）
  • ③ State 生命周期 = 单次 invoke：需要跨执行/跨节点群共享的东西必须外置（08 字典、09 消息列表、生产 Redis/DB）——与 char02 记忆思想一脉相承

六、概念自测清单（读完 10 篇应该能不假思索回答）

  1. 为什么 State(Dict) 会静默失败，而 TypedDict 能工作？（schema 由字段注解构建）
  2. TypedDict 漏声明 query 字段时会发生什么？（输入键被静默裁剪，不报错——09 篇实测）
  3. add_conditional_edges 的三个参数各是什么？（挂载点 / 路由函数 / 映射表——02 篇）
  4. RetrievalQA 里 llm=None 为什么必炸？（链的职责 = 检索+生成，没有 LLM 就没有生成——03 篇）
  5. @tool 为什么必须有 docstring？（docstring 就是给模型/框架看的 description——04 篇）
  6. StructuredTool 为什么不能直接 multiply(a=7, b=8)？（@tool 返回的是工具对象不是函数，调用要走 .invoke——04 篇）
  7. 06 篇的降级链为什么断裂？（失败信号被中间工位的格式加工破坏，下游精确匹配失配）
  8. 07 篇的降级链为什么活着？（失败信号恰好不被 replace 命中——运气不是设计）
  9. sqlite3 ":memory:" 每次连接意味着什么？（全新空库，连接关闭数据销毁——07 篇）
  10. State 和外部存储（mcp/hub）的生命周期差异？（单次 invoke vs 进程级——08 篇双 invoke 实证）
  11. 09 篇的 AgentB 数据从哪来？（a2a.receive 收信，不读 State 的 agentA_result——消息传递范式标志）
  12. 条件边和并行边的区别？（只走一条 vs 全部都走——02/10 姊妹篇）
  13. LangGraph 并行图的汇聚点为什么不会早到？（屏障语义：等所有分支完成——10 篇）
  14. 教材的 MCP/A2A 类和真实协议差在哪？（同名陷阱：真协议是跨进程标准，教材类是同进程对象——08/09 辨析）

八、给新人的学习路径（char05 版）

  1. 先跑 01：亲手复现"invoke 返回 None"，再改 TypedDict 看它活过来——建立"schema 即契约"的第一直觉（自测：能解释为什么 Dict 子类失败）
  2. 再跑 02：改路由函数的判断条件，观察走不同分支——理解"图是声明，路由是逻辑"（自测：说出条件边三参数）
  3. 读 03/04 做对比：链入图 vs 工具入图，体会粗/细粒度选型（自测：能说出 @tool 无 docstring 会炸在哪一行）
  4. 连读 05-07 做降级链专题：重点看 06 的断裂与 07 的"幸运"——这是本系列最珍贵的错误分析（自测：能画出三篇的信号传递链并标注断点）
  5. 连读 08-10 做通信专题：先辨析假 MCP/假 A2A，再对比 State 与外部存储的生命周期，最后看并行图的屏障语义（自测：能解释 08 覆盖 vs 09 累积的差异）
  6. 做练习题：每篇 HTML 的动手练习按 1→4 递进；09 练习 1（复现裁剪坑）和 10 练习 1（统计漏做比例）优先做

前置要求：char01-04 顺序学完（尤其 char04 的 initialize_agent——char05 是对"黑盒"的回应）。后续衔接：char05 补上了图的"循环"一课的最后拼图（02 条件边 + 回边 = Agent 循环的图版本），向上通往生产级图编排（checkpoint 持久化 / human-in-the-loop / 子图）。

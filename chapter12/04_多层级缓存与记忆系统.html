例 12-4 讲解：多层级缓存与记忆系统

本节核心变化：LLM 是无状态的——每次调用都是失忆的。本篇给 Agent 建立三层记忆：短期缓存（会话历史，cache.json 替代 Redis）、长期知识库（语义向量检索，替代 Chroma）、跨模型记忆共享（同一会话历史注入不同模型）。教材的 LangChain 引用有一半是虚构/废弃的，全部重写。

二、三层记忆架构

三、层级 1：JSONCache（Redis 的替代实现）

class JSONCache:
    """基于 cache.json 的键值缓存，替代 Redis 的会话历史存储"""

    def append_history(self, session_id, role, content):
        """向指定会话追加一条历史（等价 Redis rpush）"""
        sessions = self._data.setdefault("sessions", {})
        sessions.setdefault(session_id, []).append({"role": role, "content": content})
        self._save()

    def get_history(self, session_id):
        """读取指定会话的全部历史（等价 Redis lrange 0 -1）"""
        return list(self._data.get("sessions", {}).get(session_id, []))

额外设计：向量也存进 cache.json。embedding API 按调用计费——知识库不变时向量不会变，缓存后重复运行零成本。教材用 Chroma persist 实现同一目的，cache.json 同样胜任且零依赖。

四、层级 2：语义向量检索（理解 RAG 的最小实现）

# ① 查询向量化（1024 维语义向量）
qvec = embed_texts([query])[0]

# ② 与每个知识分块算余弦相似度（-1~1，越大语义越近）
scored = [(chunk, cosine_similarity(qvec, vvec))
          for chunk, vvec in zip(self._chunks, self._vectors)]

# ③ 取 top-2（教材 k=2）
scored.sort(key=lambda x: x[1], reverse=True)
return scored[:top_k]

查询: "Self-Attention 是怎么工作的"
  相似度 0.693 | 多头注意力（Multi-Head Attention）将 Self-At...

对话时的检索 top=0.850（带完整问题上下文时更高）
这就是 RAG 的本质：用户的自然语言问题和知识库里的相关段落被映射到同一个向量空间，语义相近 = 向量夹角小 = 余弦相似度高。Chroma/FAISS/Milvus 等专业向量库只是把"算相似度+排序"做得更快、支持更大规模——原理和这 30 行代码完全一致。

五、层级 3：跨模型记忆共享（记忆与模型解耦）

# 两个后端：不同模型 + 不同调用协议
CHAT_BACKENDS = {
    "backend_a": {"model": "qwen-plus",  "protocol": "native"},   # dashscope 原生
    "backend_b": {"model": "qwen-turbo", "protocol": "openai"},   # OpenAI 兼容
}

# 记忆共享的核心：历史存在 cache 里，模型只是"读客"
history = self.cache.get_history(self.session_id)   # 谁写的都能读
messages = [system(知识)] + history + [本轮输入]     # 全量注入
关于 DeepSeek 的实测说明：教材用 Qwen/DeepSeek 双厂商演示跨模型。实测当前百炼账号未开通 DeepSeek 托管（deepseek-v3 等模型名 404），故改用 qwen-plus / qwen-turbo 两个真实可用的不同模型 + 两种不同调用协议演示。记忆共享机制与用什么模型无关——历史在 cache 里，模型只是消费者；若账号开通 deepseek，把 backend_b 的 model 改回 "deepseek-v3" 即可。

为什么这体现了"解耦"？

注意 messages 的组装对两个后端完全相同（role/content 结构一致，OpenAI 兼容模式已成行业通用格式）。记忆的存取（JSONCache）与记忆的消费（任意 LLM）彻底分离——换模型、换供应商、加新 Agent，记忆层一行不用改。这正是教材"跨模型协同缺乏统一机制"问题的答案：统一机制 = 外置存储 + 标准消息格式。

例 12-3 讲解：API 负载均衡与异步任务调度

本节核心变化：例 12-1/02 的服务都是同步阻塞——客户端发请求后一直挂着等 LLM 生成完（1-2 秒甚至更久）。本篇改成异步任务模式：提交立即返回 task_id，结果稍后轮询获取。同时补上教材标题承诺却完全没实现的负载均衡，并用 cache.json 替代 Celery 对 Redis 的依赖。

一、为什么需要异步任务调度？

同步模式的天花板：一个 LLM 请求耗时 1-10 秒，Flask 默认线程数有限。100 个用户同时提问 = 请求排队 = 接口超时 = 用户体验崩塌。异步化把交互拆成两步：

  • POST /generate —— 入队即返回（毫秒级），客户端拿到 task_id
  • GET /result/{task_id} —— 客户端随时来查，好了再取

这解耦了"接收请求"和"执行任务"：接收层轻快响应，执行层慢慢消化，互不拖累。

三、核心概念 1：任务状态机

PENDING 已入队 → PROCESSING 执行中 → COMPLETED 完成  或  FAILED 失败 

# 提交：状态 PENDING，立即返回 task_id（202 Accepted）
task_id = uuid.uuid4().hex[:8]
instance = self._router.next()                # 负载均衡决定归属
self._tasks[task_id] = {"status": "PENDING", "instance": instance, ...}
self._pool.submit(self._execute, task_id, prompt, instance)
return task_id

# 工作线程体：PROCESSING → COMPLETED / FAILED（异常也要落盘）
def _execute(self, task_id, prompt, instance):
    self._tasks[task_id]["status"] = "PROCESSING"
    try:
        content = dashscope.Generation.call(...)...
        self._tasks[task_id].update(status="COMPLETED", result=content)
    except Exception as e:
        self._tasks[task_id].update(status="FAILED", result=str(e))
对照 A2A 协议：这个状态机和 char10 A2A 的 Task 七态（submitted → working → completed/failed）思想完全一致——任务有生命周期，客户端靠状态轮询驱动交互。学会本篇就理解了 A2A Task 状态机的一半。

四、核心概念 2：Round-Robin 负载均衡

class RoundRobinRouter:
    """轮询分发器：把任务交替分配给多个后端实例"""
    def next(self) -> str:
        with self._lock:                      # 多线程安全
            name = self.instances[self._index % len(self.instances)]
            self._index += 1
            self._counters[name] += 1
            return name

五、核心概念 3：cache.json 持久化（替代 Redis）

Redis 在教材里承担任务状态存储（backend）。按项目约定改用运行目录 cache.json：

{
  "e91803a0": {
    "status": "COMPLETED",
    "instance": "instance-0",
    "prompt": "用一句话介绍负载均衡",
    "result": "负载均衡是一种将网络流量或计算任务智能分发到多个服务器...",
    "created_at": "18:41:42"
  },
  ...
}

持久化的两个时机

  • 提交时落盘——任务刚创建就写入，服务重启后 task_id 仍可查询（不丢任务）
  • 终态时落盘——COMPLETED/FAILED 时更新写入，结果持久保留
内存与文件的一致性：所有读写都在 _lock 保护内进行——先改内存字典，再整体写 JSON 文件。单进程内这是正确做法；多进程部署时文件锁会失效，那才是必须上 Redis 的时机（生产演进路径已在代码注释标明）。

九、动手练习

  1. 任务超时清理：给任务加 expires_at 字段，实现一个后台线程定期清理 1 小时前的 COMPLETED 任务，防止 cache.json 无限增长。
  2. 加权轮询：把 RoundRobinRouter 改成加权轮询（weight=[3,1]），instance-0 处理 3/4 流量——模拟"强弱不一的机器"。
  3. 任务优先级：提交时带 priority 字段，执行线程总是优先取高优先级任务（提示：用 queue.PriorityQueue 替代 ThreadPoolExecutor 的隐式队列）。
  4. SSE 推送替代轮询：参考 char10-05 的 TaskStatusUpdateEvent，用 Flask 的 Response(stream_with_context(...), mimetype='text/event-stream') 把 /result 改成服务器主动推送状态变化。
  5. 故障转移：模拟 instance-1 挂掉（如任务执行时抛特定异常），路由器自动把后续任务全部导向 instance-0——体验"负载均衡的容错职责"。

逐段代码讲解

4.1 clean_text：两行正则的清洗策略（原样保留）

def clean_text(text):
    text = re.sub(r"[^\u4e00-\u9fa5。！？；，、（）——""《》：A-Za-z0-9]", "", text)
    text = re.sub(r"\s+", "", text)
    return text

第一行解读：[^…] 里的 ^ 取反——"不在白名单里的全删掉"。白名单包含：中文汉字 Unicode 范围、中文常用标点（句号感叹号问号分号顿号逗号全角括号破折号引号书名号冒号）、英文字母、数字。注意细节：白名单里有全角括号 （） 但没有半角 ()——原始文本用全角所以保留了；换成半角括号会被删掉。

第二行解读：\s+ 匹配一个或多个空白字符（空格、换行、Tab），替换为空——多段文本被压成一整行，句子之间靠保留下来的句号分隔。

4.2 split_sentences：零宽断言断句（原样保留）

return re.split(r"(?<=[。！？])", text)

(?<=...) 是正向后顾断言——"在句号/叹号/问号后面断开，但把它本身留在分割结果里"。所以每个 chunk 句尾都有标点。没有断言的话 re.split(r"[。！？]", text) 会把标点也当成分隔符吃掉，句尾标点消失。

4.3 generate_chunks：贪婪拼接（原样保留）

def generate_chunks(sentences, max_len=60):
    chunks = []
    current_chunk = ""
    for sentence in sentences:
        if len(current_chunk) + len(sentence) <= max_len:
            current_chunk += sentence
        else:
            if current_chunk:
                chunks.append(current_chunk)
            current_chunk = sentence
    if current_chunk:
        chunks.append(current_chunk)
    return chunks

逻辑和 02 篇 RecursiveCharacterTextSplitter 的贪婪合并完全同构——差别只是 02 篇有递归降级机制（一种边界切不动换更粗的边界），本篇没有。实测中 max_len=80 且每句都没到上限，所以一句一块、共 5 块。如果 max_len 改小到 50，长句会被迫拆开——这就是 02 篇递归降级存在的意义（字符级硬切在本篇会把句子拦腰斩断）。

隐藏教学点：re.split 的末尾空串陷阱

实测 sentences=6 但 chunks=5——差在哪一个？

文本末尾是句号（"方案。"），re.split(r"(?<=[。！？])", text) 在最后一个句号后也会分割一次，产生一个空字符串元素：

# 伪代码演示
>>> re.split(r"(?<=x)", "axbxc")   # 在 x 后断
['a', 'b', 'c', '']                 # 3 个分隔符 → 4 段，最后一段是空串！

5 个句号 → 6 个元素 = 5 个真句子 + 1 个空串。generate_chunks 遍历空串时 len("")=0，0 + len(current_chunk) <= max_len 永远成立——空串被合并进了上一块，所以最终 chunks=5 而非 6。生产解法：加一行过滤 sentences = [s for s in sentences if s]。

生产视角

  • 白名单正则的维护成本：本篇列了一堆标点，真实场景遇到新标点（波浪线 ~、省略号 …、数学符号 ∞ 等）要不停加——更灵活的写法是"只保留中文、英文、数字"加 [^\u4e00-\u9fa5A-Za-z0-9] 然后 \.strip()，让中文自然边界成句
  • 零宽断言的陷阱：split_sentences 只认。！？——省略号 …、问号？ 全半角混用、句号后有引号的情况会漏切
  • re.split 末尾空串必须过滤（第五节）
  • 自定义 vs 现成的选型：一次性处理/学习用途用自定义；生产用 langchain_text_splitters（支持递归降级、按结构切、带 metadata），但要理解它的内部逻辑（本篇就是那个内部逻辑）

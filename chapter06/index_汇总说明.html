嵌入模型签名固定为 List[np.ndarray]——换模型只改 get_qwen_embedding 内部，FAISS 构建和检索零改动（05/06 篇共同实证）。

不变式 2：显式 vs 隐式 RAG
显式 RAG（07/08/09）：                隐式 RAG（05/06）：
  开发者写死"先检索、再拼 prompt、再调 LLM"  Agent function calling
  流程固定，必然走检索路径                  模型自主决策是否调工具
  新人一眼看懂 RAG 底层                    更优雅但藏了底层逻辑

关键认识：隐式 RAG 只是把显式 RAG 的三个步骤，交给模型在 Agent 循环里自主决策是否执行——底层逻辑完全同构。

不变式 3：RAG 的核心公式
RAG = 检索（Retrieval） + 生成（Generation）
检索 = 向量化 → 索引构建 → 相似度搜索   ← char06 01-03
生成 = prompt 里放检索结果 → LLM 基于上下文回答   ← char06 07-09

五、四笔学费（教材代码问题谱系）

学费 1：requests 嵌入 API 端点 2025 年格式已变（05 篇实测）

教材用的 text-embedding-v1 端点，2025 年实测返回 {"code": "BadRequest.IllegalInput"}，响应结构也不是教材预期的 data["output"]["embeddings"]——API 格式已变。解法：用 LangChain 封装的 DashScopeEmbeddings（01/03 篇已验证稳定）。

学费 2：LangChain 封装 = 原生 FAISS 的黑盒（01 vs 05）

01 篇一行 FAISS.from_documents(docs, emb_model) 底下干的就是 05 篇手写的 20 行：faiss.IndexFlatL2(dim) → vstack → add。理解了 05 篇的原生操作，01 篇就不再是黑盒。

学费 3：教材假标题/假功能
  • 03 篇标题叫"带语义找回功能 Agent"——实际无 Agent，只有 similarity_search
  • 08/09 篇标题提"DeepSeek"——实际是硬编码 if/elif，根本没调任何 LLM
学费 4：re.split 末尾空串陷阱（04 篇）

re.split(r"(?<=[。！？])", "方案。") → ['方案。', '']——文本末尾是句号时 split 多产生一个空串，被后续代码静默合并进最后一块。生产必须加 [s for s in sentences if s] 过滤。

八、生产视角：RAG 优化四道门槛

  1. rerank 重排序：FAISS top-20 → CrossEncoder 精排选 top-3（生产标准做法，bge-reranker-v2-m3）
  2. 混合检索：向量检索（语义）+ BM25（关键词）→ 融合（09 篇双通道的思路升级）
  3. 索引持久化：FAISS faiss.write_index/read_index；Chroma 默认持久化到本地文件夹
  4. 长上下文管理：超出窗口时递归摘要 / MapReduce 压缩（先每段总结→总结再合并）

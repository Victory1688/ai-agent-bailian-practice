一、这份代码整体在做什么（一段话讲给新人）

本篇是 char06 最有架构高度的一篇——解决了 RAG 的核心痛点：信息同时存在于非结构化文本和结构化数据中，单一检索方式兼顾不了两类数据。解决方案是双通道查询 + 结果融合：文本通道（FAISS 语义搜索政策新闻）+ 数据通道（pandas 过滤财政年度数据）→ 两个 context 拼进同一个 prompt → qwen-plus 综合生成回答。

标题里的 "DeepSeek" 是假的

教材标题写"Qwen和DeepSeek"，暗示 FiscalDataQueryTool 里有 DeepSeek-V1 做 NL→SQL，但原代码实际是硬编码 if/elif 关键词匹配——根本没调任何 LLM。改写时保持原状，因为真正的 NL→SQL 会让本篇偏离"混合检索架构"的教学重心（NL→SQL 是 char01-03 的任务建模问题）。

4.3 build_prompt：双通道融合

def build_prompt(query, text_context, data_context):
    return f"""你是财税智能助手，拥有文本政策知识和财政结构化数据。
【政策解读】：{text_context}          ← 文本通道结果
【财政数据】：{data_context}          ← 数据通道结果
请结合以上信息回答用户问题：{query}
回答应准确、简洁、有数据支撑。"""

两个 context 拼成一个 prompt，LLM 同时看到政策文本和数据数值——这就是"融合"的本质：不融合检索逻辑，融合给 LLM 的输入。

实测回答：LLM 如何综合双通道信息

实测回答（qwen-plus 综合双通道）
2020年中国的财政支出是多少？相关政策有没有调整说明？

--- Agent回答 ---
2020年中国政府支出占GDP比重为25.5%（数据通道），
  2020年GDP为101.6万亿元（模型内部知识），
  据此计算：财政支出 ≈ 25.91万亿元（LLM 综合推理）。

相关政策调整（文本通道）：
✅ 实施积极的财政政策，减税降费超2.5万亿元；
✅ 聚焦"六稳""六保"，强化逆周期调节；
❌ 2024年专项债额度3.9万亿元（识别出与2020无关）。

LLM 综合推理的三个层次：①直接从数据通道拿到 25.5%；②结合内部知识（GDP 数值）算出支出金额；③从文本通道拿到政策后，还能识别出哪些政策年份不对、排除无关信息——这就是 LLM 作为"融合器"的价值。

双通道 vs 单通道：为什么需要两个

三种典型场景对照
用户问题单文本通道单数据通道双通道融合
"2020年财政支出多少？"只能返回"25.5%"，无政策背景只能返回"25.5%"，无政策背景数据+政策，完整回答
"有什么积极财政政策？"能返回政策文本只能返回数值政策文本+数据支撑
"2020年减税降费规模？"能返回"2.5万亿"查不到文本检索拿到+数据通道验证年份

关键洞察：用户问题天然横跨"是什么（数据）"和"为什么（政策）"两个维度——单通道只能答一半。双通道是 RAG 从"知识问答"升级到"业务问答"的必经之路。

生产视角

  • 双通道触发条件：用户问题含数值/年份/金额 → 自动触发数据通道；含"政策/规定/说明" → 自动触发文本通道；混合问题 → 双通道全跑（本篇简化版直接全跑，生产用意图识别智能触发）
  • 数据通道的 NL→SQL：本篇用硬编码 if/elif，生产用 LLM function calling 生成 SQL → 执行 → 返回结果（char01-03 任务建模就是这个）
  • 融合不止拼接：简单拼接是最基础的融合；更高级的有 Cross-Encoder rerank（给两通道结果重新排序）、MapReduce（每通道先总结→总结再合并）
  • 标题里的 "DeepSeek"：教材虚构，生产可以真调 DeepSeek 做 NL→SQL（deepseek-chat + SQL schema 作为 context），与 qwen-plus 主 LLM 配合

动手练习

  1. 对比单通道 vs 双通道：把 data_context 注释掉（只跑文本通道），把 text_context 注释掉（只跑数据通道）——对比两次回答的完整度差异，体会双通道的必要性。
  2. 改 FiscalDataQueryTool 加年份：扩展 if/elif 支持更多年份查询——观察硬编码规则的脆弱性（年份越多越难维护），体会生产为什么需要 NL→SQL。
  3. 真 NL→SQL 改造：用 qwen-plus function calling 把 FiscalDataQueryTool 改成"LLM 生成 SQL → pandas 执行 → 返回结果"——连接 char01-03 的任务建模知识。
  4. 融合策略升级：在 build_prompt 里给 text_context 和 data_context 各加一个"重要性权重"字段，让 LLM 知道哪个通道结果更可信——体会融合的精细化控制。

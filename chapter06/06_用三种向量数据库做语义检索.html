一、这份代码整体在做什么（一段话讲给新人）

本篇是 "同一个嵌入模型、同一份数据，换三种向量数据库做同一件事" 的对比实验——六步走完"抓数据→向量化→三种索引→Agent 调用→生成回答"的完整闭环，最核心的教学价值在于展示三种向量数据库的部署形态差异。改写后 FAISS 和 Chroma 真实跑通，Weaviate 因需 Docker 服务端注释保留（本机无 Docker）。

三种向量数据库部署形态对比表

FAISS 是"工具"（只有索引没有元数据管理），Chroma 是"嵌入式数据库"（自带文档管理+持久化），Weaviate 是"服务端数据库"（独立进程+REST API）——三者构成向量库的三代演进形态。选择哪种取决于部署复杂度 vs 功能需求的权衡：原型用 FAISS，轻量 RAG 用 Chroma，生产多租户用 Weaviate/Milvus/Qdrant。

逐段代码讲解

5.1 三种索引构建的 API 对照

# FAISS：numpy 矩阵 + 函数（最底层、最轻量）
index = faiss.IndexFlatL2(dim)        # 指定 L2 距离的索引
index.add(np.vstack(embeddings))        # 矩阵一次性灌入
D, I = index.search(qvec, k=3)          # 返回距离 + 索引

# Chroma：面向对象 .add/.query（封装了文档管理）
collection = chroma.EphemeralClient().create_collection(name="...")
collection.add(documents=[...], ids=[...], embeddings=[...])
result = collection.query(query_embeddings=[emb], n_results=3)

# Weaviate：RESTful API（HTTP 调用，最重量级）
client = weaviate.Client("http://localhost:8080")
client.schema.create_class({...})       # 先声明 schema
client.data_object.create({...}, "Policy", vector=vec)  # 数据带 vector 提交
result = client.query.get(...).with_near_vector(...).with_limit(3).do()

5.2 三个 Tool 类 → 纯函数 + Agent 循环

原写法：class FaissSearchTool(Tool):（继承虚构 Tool）→ class FaissSearchTool:（纯类）+ search(query) 方法。三个类的核心检索逻辑（向量化→搜 top-k→返回命中）完全原样保留，只是去掉了虚构框架的继承和 call() 命名。

生产视角

  • 选库决策树：原型/实验 → FAISS（最轻）；轻量 RAG/个人项目 → Chroma（自带持久化+元数据）；生产分布式 → Milvus/Qdrant/Weaviate（REST API + 水平扩展）
  • 嵌入模型可插拔（05/06 篇共同实证）：换模型只改 get_embeddings 内部，索引构建和检索零改动——这就是"接口签名固定"的架构设计价值
  • 多库检索的去重：同一知识库用不同向量库检索会得到部分重叠结果（如本篇）——Agent 层面需要去重/重排序（rerank）
  • Weaviate 的 Docker 启动：docker run -p 8080:8080 semitechnologies/weaviate:latest（教材注释里已提）

动手练习

  1. 对比 FAISS vs Chroma 检索结果：把 _faiss_tool.search() 和 _chroma_tool.search() 直接打印出来（不走 Agent）——同一条查询，两个库的 top-3 是否一致？体会"向量库算法差异"（FAISS L2 欧氏距离 vs Chroma 默认余弦相似度）。
  2. Chroma 持久化：把 EphemeralClient 改成 PersistentClient(path="./chroma_data")——进程结束后数据还在，再跑一次看是否需要重建集合。
  3. 验证"多库去重"问题：让 Agent 先调 FAISS 再调 Chroma，观察两个结果的重叠度——思考生产中如何解决（rerank 重排序 / 合并去重）。
  4. 进阶：Milvus/Qdrant 初体验：了解 Milvus（pip install pymilvus）和 Qdrant（pip install qdrant-client）的客户端 API——对比三种部署形态的调用风格差异。

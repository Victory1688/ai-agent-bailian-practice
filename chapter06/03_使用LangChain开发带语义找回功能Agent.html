一、这份代码整体在做什么（一段话讲给新人）

本篇是 01 篇"入库→检索"流程的强化重演：五条 AI 知识文本向量化存入 FAISS，查询"什么是RAG机制？"，取最相似的 k=2 条返回——新增的知识点是 k 参数（召回条数控制）和嵌入模型选型的思考。
两个诚实辨析先行：①标题叫 Agent，但代码里没有 Agent（无大模型调用、无决策循环）——本质是语义检索，即 RAG 的"R"，等检索结果接入大模型生成答案才是完整 RAG/Agent；②教材用的 all-MiniLM-L6-v2 是英文向量模型，检索中文知识库会明显失真——本篇改用百炼中文向量模型（与 01 篇同款），原写法保留为注释。

逐段代码讲解

4.1 与 01 篇的差异点：k 参数（原样保留）

matched_docs = db.similarity_search(query, k=2)   # 01 篇用默认 k=4，本篇显式 k=2

k 的权衡：RAG 后续要把召回文本塞进大模型的上下文窗口——k 太小可能漏掉真正有用的知识（答案不在 Top2 里），k 太大塞进一堆无关文本（浪费 token 且稀释模型注意力）。生产中 k 通常取 3-8，配合相似度分数阈值一起调。

4.2 其余三段（原样保留）

db = FAISS.from_documents(documents, embedding_model)   # 入库+建索引（同 01 篇）
matched_docs = db.similarity_search(query, k=2)          # 检索
for idx, doc in enumerate(matched_docs): ...             # 输出

本篇最重要的知识点：嵌入模型必须匹配语言

教材原方案的三重问题与改写决策
教材原写法问题
from langchain.embeddings import HuggingFaceEmbeddings0.x 路径断裂（同 01 篇）
HuggingFaceEmbeddings(model_name="sentence-transformers/all-MiniLM-L6-v2")①需要 sentence-transformers 包 + 首次运行联网下载模型（国内需配 hf-mirror 镜像）
②all-MiniLM-L6-v2 是英文模型（384 维，在英文语料上训练）——中文句子进它的向量空间，语义距离基本失真，检索中文知识库的排序不可信

改写决策：换 DashScopeEmbeddings(text-embedding-v3)——中文原生、1024 维、与对话模型共用一把钥匙（与 01 篇一致，符合全系列"统一 dashscope"约定）。FAISS 和检索代码一行不动——嵌入模型可插拔正是 LangChain 抽象的价值。

真实运行输出与排序解读

已在本机实际运行验证（百炼 text-embedding-v3 真实向量化）
[Top 1] RAG机制结合检索系统与生成模型进行问答
[Top 2] OpenAI模型支持函数调用与多轮对话

解读两个层次：

  • Top1 无悬念：与查询共享"RAG机制"四字且语义同题——语义检索的"保底能力"（连关键词都重合的当然第一）
  • Top2 值得细品：它在"LangChain是开发框架 / 向量数据库支持语义搜索 / 嵌入模型将文本转向量"四个候选中胜出，但优势细微——这几条同属"AI 技术能力描述"句式，语义距离非常接近，最终排序由向量的细微差异决定。启示：当知识条目语义相近时，纯向量检索的排序会不稳定——生产的解法是混合检索（向量 + 关键词 BM25）或重排序（rerank 模型精排）

知识补充：本地嵌入模型的完整路线（教材意图的另一种实现）

如果想走教材的 HuggingFaceEmbeddings 本地路线

本地嵌入模型的价值：零 API 成本、数据不出门、离线可用。完整步骤：

  1. 安装依赖：pip install sentence-transformers（自动带上 torch/transformers，约 2GB）
  2. 国内镜像：设置环境变量 HF_ENDPOINT=https://hf-mirror.com，否则模型下载会卡住
  3. 选中文模型（关键！）：不要用教材的英文 MiniLM，选 BAAI/bge-small-zh-v1.5（512 维，中文效果好，约 100MB）或 BAAI/bge-large-zh-v1.5
  4. 代码只改一行：HuggingFaceEmbeddings(model_name="BAAI/bge-small-zh-v1.5")

选型对照：API 向量（本篇实际方案）胜在中文质量与零部署，适合快速开发；本地向量胜在数据隐私与零调用成本，适合内网/大规模批量。两者 FAISS 侧完全同构，切换成本一行代码。

生产视角

  • k 与阈值的组合：只调 k 不够，用 similarity_search_with_score 看分数——低于阈值的候选宁可不召回（"不知道"好过"乱检索"）
  • 语义相近条目的排序不稳定（本篇 Top2 现象）→ 混合检索（向量+BM25）+ rerank 精排是标配解法
  • 知识库质量 > 模型质量：5 条短句谁都能检索好；真实知识库的条目设计（每条一个主题、避免互相重复）对召回的影响比换模型更大
  • 本篇仍是"裸检索"：离完整 RAG 还差一步——把召回文本作为上下文喂给大模型生成答案（后续篇）

动手练习

  1. k=5 全召回：改成 k=5，看完整排序——五个候选的相对位置就是语义距离的完整画像（哪两条排最后？符合你的直觉吗）。
  2. 看分数：换 similarity_search_with_score，打印 Top2 的 L2 距离——用数字验证"Top2 优势细微"的判断。
  3. 换查询：query 改成"怎么让大模型调用外部工具？"——预测 Top2 会怎么变（提示：函数调用那条可能上位），跑完对照。
  4. 本地模型初体验（进阶）：按第七节路线装 sentence-transformers + 下载 bge-small-zh-v1.5，把嵌入模型换成它再跑——对比两种方案的 Top2 是否一致，体会"嵌入模型决定排序"。

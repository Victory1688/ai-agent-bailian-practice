本篇是 char06 第一篇完整 RAG 闭环：抓取金融新闻 → 向量化 → FAISS 索引 → Agent 语义检索工具 → qwen-plus 根据检索结果生成自然语言回答。前 01-04 篇分别教了切片、清洗、向量化、检索——本篇把它们串成一个可问答的系统。

三条路线混在一起（改写前）：①虚构 qwen_agent 框架（Agent/Tool/Message 已在 char02 多次实战确认不存在）→ 改写为 dashscope function calling；②原生 requests 调百炼嵌入 API（2025 年端点格式已变，实测报 BadRequest）→ 改写为 DashScopeEmbeddings（LangChain 封装，接口稳定）；③原生 faiss + numpy——原样保留，这是本篇最有价值的教学资产（01 篇的 FAISS.from_documents 只是把本篇 20 行代码藏进了一个方法里）。

逐段代码讲解

4.1 嵌入编码函数：原生 API 变更 + 封装替换

# 原写法（注释保留）：
# QWEN_EMBEDDING_API = "https://dashscope.aliyuncs.com/api/v1/services/embeddings/text-embedding/text-embedding"
# def get_embeddings(texts):
#     response = requests.post(QWEN_EMBEDDING_API, ...)
#     return [np.array(item["embedding"]) for item in data["output"]["embeddings"]]

# 改写：签名不变，内部换成 DashScopeEmbeddings
def get_embeddings(texts: List[str]) -> List[np.ndarray]:
    raw = _emb_model.embed_documents(texts)
    return [np.array(v, dtype=np.float32) for v in raw]

实测验证原写法失败：2025 年百炼嵌入端点报 BadRequest.IllegalInput: The input parameter requires json format——API 格式已变，不是鉴权问题。DashScopeEmbeddings 是 LangChain 对百炼嵌入的官方封装，内部走同一个 text-embedding-v3 模型，接口稳定。

关键设计决策：保留了 List[np.ndarray] 的返回签名——build_faiss_index(embeddings) 零改动可继续用。这就是"嵌入模型可插拔"的架构设计价值：上层（FAISS 索引）不关心下层（用什么嵌入模型）。

4.2 原生 FAISS 索引构建（原样保留）

def build_faiss_index(embeddings: List[np.ndarray]) -> faiss.IndexFlatL2:
    dim = embeddings[0].shape[0]
    index = faiss.IndexFlatL2(dim)    # L2 距离（欧氏距离）索引
    matrix = np.vstack(embeddings)     # 把列表堆成二维矩阵 [N, dim]
    index.add(matrix)                  # 一次性灌入
    return index

与 01 篇 FAISS.from_documents 的对照：01 篇的一行代码 FAISS.from_documents(docs, embedding_model) 底下干的就是：调 emb_fn → vstack → add——本篇把底层露出来。理解了本篇，就不会把 01 篇当黑盒。

4.3 Agent 循环（原 qwen_agent.Agent → dashscope function calling）

原写法 agent = Agent(tools=[search_tool]); agent.chat(...) ——qwen_agent 框架虚构（ImportError），改用 char02-06 已验证的 dashscope function calling 循环。Agent 的"检索"行为保持不变：模型自主决策调 search_finance → FAISS 搜 top-3 → 拿到结果生成自然语言回答。

实测踩坑：原生 requests 嵌入 API 的格式变更

教材的 requests 端点 2025 年已不可用（实测）
教材原代码实测结果
requests.post("https://dashscope.aliyuncs.com/api/v1/services/embeddings/text-embedding/text-embedding", json={"model": "text-embedding-v1", "input": texts})返回 {"code": "BadRequest.IllegalInput", "message": "The input parameter requires json format"}——API 格式已变
model: text-embedding-v1v1 可能已废弃；试 text-embedding-v3 同样报错
data["output"]["embeddings"]响应结构不是教材预期的格式

API 端点变更在生产中很常见——**不要直接依赖 HTTP 端点，优先用官方 SDK/LangChain 封装**（DashScopeEmbeddings 就是百炼嵌入的 LangChain 封装，接口稳定）。本次改写保留了 get_embeddings 的函数签名，只换了内部实现——这就是封装的价值。

生产视角

  • 抓取稳定性：国开证券官网 API 国内网络可能无法直连——本篇已加兜底；生产用自有知识库（本地文件/数据库）
  • 索引持久化：内存 FAISS 进程结束消失 → faiss.write_index / faiss.read_index 落盘
  • Embedding 模型升级：API 端点会变，模型会升级 → 用 LangChain 封装 + 函数签名固定，换实现一行代码
  • FAISS IndexFlatL2 只适合小库：生产用 IndexIVFFlat / IndexHNSW（加速大规模检索）
  • RAG 检索质量的关键是知识库设计：本篇 6 条模拟短句谁都能检索好；真实知识库的文档粒度、关键词覆盖、与查询的语义距离决定了检索效果——再强的模型也救不了糟糕的知识库

组一 · 单 Agent 五模块架构（理论视角）

回答"一个 Agent 由哪几块组成"。抽象出接口 / 感知 / 认知 / 执行 / 记忆五大模块，外加编排、安全、可观测、成本四条横切支撑。
源文件：llm-agent-architecture.svg

读图要点

  • 接口模块是边界层，把外部请求/事件翻译成 Agent 内部统一形态，并负责输出渲染；它常被并入感知与执行，是否独立计为第 5 个模块取决于划分粒度。
  • 认知模块是决策核心（由 LLM 驱动），实际包含三件事：规划（任务分解）、推理（含工具选择）、反思（自我纠错）；生产系统还会加一层模型路由/降级。
  • 记忆模块是横切能力：认知模块读写它（检索 + 回写），执行模块把任务轨迹写入它；工程上分短期（上下文窗口）/ 长期（向量库 RAG）/ 情景（轨迹）/ 语义（画像规则）四层。
  • 左侧虚线是 ReAct 循环：执行结果作为 Observation 回灌到感知与认知，形成 思考 → 行动 → 观察 的迭代。
  • 支撑层不单列流程，但必须一开始就设计：编排调度、安全与对齐（护栏）、可观测与评估、成本与限流。

③ - 4　微服务 → AI Agent 全技术域平移总图（v2·查漏版）

20 个技术域逐一穷举Java 栈 / Python AI 栈 / 状态徽章≈60% 可平移
源文件：微服务到AI平移总图.svg　·　配套文字：微服务到AI架构平移对照-全技术域版.md

组三读图要点（给微服务架构师）

  • 能平移的：可观测（≈Micrometer/Trace）、容错五件套（≈Sentinel/Hystrix/Resilience4j）、网关鉴权限流、Redis 会话（≈memory）、MCP（≈OpenAPI 规范）、Agent Card（≈Nacos 服务元数据）。
  • 两处反转：① 编排层——调用链不再由代码写死，而由模型运行时决定；② 工具层——"错误是数据不是故障"，工具永不抛异常，错误要回流给模型。
  • 一处新增：Token 成本 —— 微服务没有直接对应物，最接近的是 API 配额管理，但它是 AI 架构的一等公民。
  • Redis 可直接换：ch12 教学版用 cache.json 替代 Redis，你完全可以换成真 Redis；并且应该用 Lua 脚本替代教材里"get/decr 三步非原子"的写法。
  • 要"查漏"看 ③-4：v1（分层视角，见 ③-1~③-3 右侧青栏）帮你先建立整体感；v2 总图按 20 个技术域 穷举 Java 栈 → Python AI 栈，逐格标注 🟢直接平移 / 🟡需要重构 / 🔴全新领域。绝大多数技术场景都能在这张表里找到对照。
  • 量化结论：～60% 直接平移（网关/限流/熔断/可观测/鉴权/连接池）、～25% 需要重构（编排/一致性/幂等/测试/缓存）、～15% 全新领域（RAG/上下文工程/Token 成本/Prompt 工程/幻觉治理）。你的基础设施经验几乎全额可用，业务编排经验要重构，AI 特有部分是新的 30%。

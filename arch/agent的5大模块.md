# 一、Agent的模块划分

> 
> 感知模块、认知模块、执行模块、记忆模块、接口模块 ✅ 这个划分逻辑通顺，属于**从Agent拟人化心智视角**拆分，很适合做业务Agent架构设计。
> 业界还有另外一套划分（Planner/Tool/Memory等），二者只是视角差异，不冲突。

## 各模块职责定义（对齐你的5模块）

1. **感知模块 Perception**
 负责接收外部原始输入，做预处理。
   - 用户对话、文件上传、事件消息、系统推送
   - 输入清洗、意图初步分类、敏感过滤、信息抽取
   - 输出结构化用户事件，交给认知模块> 
   > 类比：人的五官，接收外界信号
2. **记忆模块 Memory**
 存储、检索、管理全部状态信息，分三类：
   - 短期记忆：本轮对话上下文（窗口内）
   - 长期记忆：用户画像、偏好、历史任务、持久化事实（向量库/DB）
   - 工作记忆：当前任务中间状态、规划步骤、工具返回临时结果> 
   > 类比：大脑记忆区，记忆召回结果送入认知模块作为上下文
3. **认知模块 Cognition（核心，大模型所在层）**
 Agent的大脑，由LLM + 规划器 + 反思校验器组成
   - 任务拆解（Planner）、推理决策、是否调用工具
   - Prompt编排、思维链/ReAct推理、自我反思、幻觉校验（harness）
   - 生成行动计划、工具调用指令或者最终回答> 
   > 类比：思考、判断、决策
4. **执行模块 Action**
 负责执行认知模块输出的动作指令
   - Tool调用、MCP客户端、API请求、代码沙盒、数据库读写
   - 工具参数校验、调用重试、结果封装、异常捕获
   - 工具执行结果回传给感知/认知模块，进入下一轮推理循环> 
   > 类比：手脚，执行行动
5. **接口模块 Interface**
 对外/对内的标准接入层
   - 面向用户端：API、WebUI、SDK
   - 面向外部系统：MCP服务、第三方业务系统、消息队列
   - 内部：模块之间的消息总线、统一数据结构体> 
   > 类比：各类对外通讯通道

# 二、文本架构图（可直接复制到Markdown，支持Mermaid渲染）

```
flowchart TD
    USER[用户 / 外部系统] --> INTERFACE[接口模块<br/>Interface]
    
    INTERFACE --> PERCEPTION[感知模块<br/>Perception<br/>输入清洗｜意图识别｜事件抽取]
    
    PERCEPTION --> COGNITION[认知模块<br/>Cognition<br/>LLM｜任务规划｜推理反思｜Prompt编排｜结果校验]
    
    MEMORY[记忆模块<br/>Memory<br/>短期上下文｜长期用户记忆｜任务工作记忆] -.召回上下文.-> COGNITION
    COGNITION -.写入任务状态.-> MEMORY
    
    COGNITION --> ACTION[执行模块<br/>Action<br/>工具调度｜MCP调用｜API执行｜异常重试]
    
    ACTION -.工具返回结果.-> PERCEPTION
    ACTION -.执行状态回写.-> MEMORY
    
    ACTION --> INTERFACE
    COGNITION -.最终应答.-> INTERFACE
    
    INTERFACE --> USER
```

## 数据流简要说明

1. 用户请求 → 接口模块接入
2. 感知模块做输入预处理，结构化消息
3. 认知模块从记忆模块召回相关历史信息，结合当前输入，做任务推理规划
4. 认知模块决定：直接回答，或者下发动作指令给执行模块
5. 执行模块调用MCP/外部工具，拿到结果
6. 工具结果回流到感知，再次送入认知，开启新一轮思考循环（ReAct循环）
7. 任务完成后，认知生成最终回答，经由接口模块返回用户；同时更新记忆

# 三、补充说明

这个5模块模型是**拟人Agent架构**，优点：

- 容易理解、适合写方案文档、做团队沟通
- 和你前面聊的Prompt工程、Memory、MCP、harness校验可以完美嵌入

> 
> 认知模块内部包含了你说的harness校验能力：自我反思、事实校验、输出格式约束。
> MCP放在执行模块，作为标准化工具接入能力。

一、这段代码要做什么

实现一个带安全注销机制的临时任务 Agent：任务完成后，Agent 执行完整的注销流程——先审计留底、再释放存储、最后写精简日志——确保不留下僵尸文件和内存泄漏。

核心教学点：注销（shutdown）vs 清理（cleanup）

char02 五篇的 Agent 生命周期完整覆盖：
01 → 骨架搭起来（能启动能说话）
02 → 状态追踪（能记住中间变量）
03 → 持久化记忆（重启不丢记忆）
04 → 注销清理（用完能干净退出）
05 → 外部 API（能力边界扩展）

04 篇填补的是"Agent 用完之后怎么办"这个空白——没有注销机制的 Agent 就像用完不关机的电脑，长期运行会出问题。

四、核心概念速查表

概念代码中的实现一句话解释
注销（shutdown）ManagedAgent.shutdown()完整的退出流程：审计留底 → 释放资源 → 写摘要
清理（clear）LoggingMemory.clear()单步操作：删除 JSON 文件（释放存储）
审计留底shutdown 步骤 1 的 memory.save()先保存再删除，确保对话历史不丢失，事后可回溯
摘要日志shutdown 步骤 3 的 _log.txt 写入JSON 完整但臃肿，txt 精简便于快速查看
资源泄漏未注销时 JSON 文件残留 → 磁盘占满长期运行的 Agent 必须有注销机制

五、逐段讲解（5 个代码块）

块 1：LoggingMemory（第 32-51 行，和 03 篇的 PersistentJSONMemory 对照看）

class LoggingMemory:
    """支持写入日志文件的持久化记忆，注销时 clear() 删除 JSON 文件"""
    def __init__(self, session_id: str):
        self.session_id = session_id
        self.memory_file = os.path.join(MEMORY_PATH, f"{session_id}.json")
        self.logs = []                              # 运行时消息列表（注意：03 篇叫 self.messages）

    def add_message(self, message: dict):
        self.logs.append(message)

    def get(self):
        return self.logs

    def save(self):
        """把当前全部消息写入 JSON 文件"""
        os.makedirs(MEMORY_PATH, exist_ok=True)
        with open(self.memory_file, "w", encoding="utf-8") as f:
            json.dump(self.logs, f, ensure_ascii=False, indent=2)

    def clear(self):
        """注销时删除 JSON 文件（释放存储资源）"""
        if os.path.exists(self.memory_file):
            os.remove(self.memory_file)
和 03 篇 PersistentJSONMemory 的两个区别
  • 03 有 load()，04 没有：03 篇要"中断恢复"所以需要 load 读历史；04 篇是临时任务，不需要恢复
  • 04 有 clear()，03 没有：03 篇要持久化所以不该删；04 篇要注销所以必须删

块 4：ManagedAgent（第 111-145 行，注销机制的核心封装）

class ManagedAgent:
    def __init__(self, session_id: str):
        self.session_id = session_id
        self.memory = LoggingMemory(session_id)
        self.config = {
            "name": "CleanableAgent",
            "model": "qwen-plus",
            "temperature": 0.2,    # 低随机性，任务助手不要太跳
            "max_tokens": 256,    # 短回答，节省 tokens
            "system_message": SYSTEM_MESSAGE
        }

    def chat(self, user_input: str) -> str:
        result = agent_chat(self.config, user_input, self.memory)
        return result

    def shutdown(self):
        """注销流程：保存 → 清理 → 写摘要日志"""
        print(">> 执行Agent注销流程...")

        # 步骤 1：先保存 JSON（注销前留底，事后审计用）
        self.memory.save()

        # 步骤 2：删除 JSON 文件（释放存储资源）
        self.memory.clear()

        # 步骤 3：写精简的文本摘要日志（便于事后快速查看）
        log_file = os.path.join(MEMORY_PATH, f"{self.session_id}_log.txt")
        with open(log_file, "w", encoding="utf-8") as f:
            for item in self.memory.logs:
                ts = datetime.datetime.now().strftime("%Y-%m-%d %H:%M:%S")
                role = item.get("role", "unknown")
                content_preview = (item.get("content", "") or "")[:50]
                f.write(f"[{ts}] {role}: {content_preview}\n")

        print(">> Agent已成功注销并释放资源")
shutdown 三步：为什么不是"直接删"？

如果直接 clear()（删 JSON）：对话历史就没了，万一需要审计或复盘就追不回来。
现在的三步：先 save() 留底 → 再 clear() 释放 → 最后写精简 txt 摘要。JSON 和 txt 不共存——clear() 已经删了 JSON，txt 是唯一残留，但它是精简的、只读的日志，不是完整对话记录。

块 5：run_task_session（第 148-172 行）

def run_task_session():
    session_id = "temp_agent_001"

    # 演示可重复运行：清旧残留
    for suffix in [".json", "_log.txt"]:
        f = os.path.join(MEMORY_PATH, f"{session_id}{suffix}")
        if os.path.exists(f):
            os.remove(f)

    agent = ManagedAgent(session_id)

    print(agent.chat("请帮我完成今天的日报任务"))
    print(agent.chat("现在关闭智能体"))

    agent.shutdown()

    # 关键验证：注销后 JSON 已删、日志文件存在
    json_path = os.path.join(MEMORY_PATH, f"{session_id}.json")
    log_path = os.path.join(MEMORY_PATH, f"{session_id}_log.txt")
    print(f"\n验证：JSON 文件存在={os.path.exists(json_path)}（应为 False）")
    print(f"验证：  日志文件存在={os.path.exists(log_path)}（应为 True）")

八、注销机制的生产级增强方向

当前实现（教学版）生产版增强为什么
shutdown 手动调atexit / try-finally 自动调程序崩溃时也要释放资源，不能等用户手动
JSON 直接删移到回收目录 + TTL 过期清理误删可恢复，留 7 天缓冲期
单线程 agent_chat多 Agent 进程池 + 超时自动销毁多个 Agent 并发运行，不能等用户逐个调 shutdown
无异常保护shutdown 本身 try-except注销过程出错（如磁盘满）不能让主流程崩
无监控注销事件上报监控系统知道有多少 Agent 正常退出、多少异常退出

九、动手练习

  1. 手动验证注销效果：运行脚本 → 检查 JSON 文件不存在、log.txt 存在 → 用记事本打开 log.txt 看内容格式。
  2. 破坏实验：删掉 shutdown() 里的 self.memory.clear()，连续运行两次——第二次会生成 JSON 文件残留，体会"资源泄漏"是什么样子。
  3. 加异常保护：在 shutdown() 外面包一层 try-except，模拟 clear() 失败（如文件被占用）时主流程不崩。
  4. 加 atexit 自动注销：查一下 Python 的 atexit.register()，让程序退出时自动调 shutdown()，不需要用户手动调。
  5. 思考题：Agent 执行中崩溃了（比如 Python 进程被 kill），shutdown() 根本调不到——这种情况怎么清理残留文件？查一下"信号处理 / 僵尸进程清理"。

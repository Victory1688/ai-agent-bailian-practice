四、核心概念速查表

概念代码中的实现一句话解释
SQLiteimport sqlite3（Python 标准库）轻量级嵌入式数据库，单文件 .db，无需单独安装服务
INSERT 写入INSERT INTO employees (name, department, title) VALUES (?, ?, ?)向表中插入一行记录
SELECT 查询SELECT ... FROM employees WHERE name = ?按条件查询，name 为空则查全部
? 参数化占位符(name, department, title) 元组传参防 SQL 注入的标准写法（绝不能用字符串拼接 SQL）
事务提交conn.commit()INSERT/UPDATE/DELETE 后必须 commit，否则数据不真正落盘
资源关闭try/finally 里的 conn.close()数据库连接用完必须关，否则长期运行会耗尽连接池

五、逐段讲解（4 个代码块）

块 1：init_db + add_employee + query_employee（本文件的教学核心）

def add_employee(name: str, department: str = "", title: str = "") -> str:
    try:
        conn = sqlite3.connect(DB_PATH)      # ① 打开连接
        cursor = conn.cursor()
        cursor.execute(
            "INSERT INTO employees (name, department, title) VALUES (?, ?, ?)",
            (name, department, title)        # ② 元组传参（防注入！）
        )
        conn.commit()                        # ③ 提交事务（必须！）
        conn.close()                         # ④ 关闭连接
        return f"员工{name}添加成功"
    except Exception as e:
        return f"添加失败：{str(e)}"          # 错误也返回字符串，不抛异常

def query_employee(name: str = "") -> str:
    try:
        conn = sqlite3.connect(DB_PATH)
        cursor = conn.cursor()
        if name:
            cursor.execute("SELECT ... WHERE name = ?", (name,))
        else:
            cursor.execute("SELECT ... FROM employees")   # 不传参数 → 查全部
        rows = cursor.fetchall()              # 取出所有结果行（list of tuple）
        conn.close()
        ...
数据库操作的"四步标准模板"
  1. 打开连接：conn = sqlite3.connect(path)
  2. 执行 SQL：cursor.execute(sql, params)（参数化占位符 + 元组传参）
  3. 提交/获取结果：写入操作要 commit()；查询操作要 fetchall()
  4. 关闭连接：conn.close()（finally 里最安全）

块 2：SQL 注入防护（新人最容易忽略的安全点）

# ✅ 正确写法（参数化，数据库驱动自动转义）
cursor.execute("INSERT INTO employees VALUES (?, ?, ?)", (name, dept, title))

# ❌ 危险写法（字符串拼接，用户输入会直接拼进 SQL）
cursor.execute(f"INSERT INTO employees VALUES ('{name}', '{dept}', '{title}')")
# 如果用户输入 name = "王小明'); DROP TABLE employees; --"
# 拼出来就是：INSERT ... VALUES ('王小明'); DROP TABLE employees; --', ...)
# 表直接被删！
为什么用 ? 占位符 + 元组传参？

SQL 注入是 OWASP Top 10 安全风险第 3 名。参数化查询是唯一可靠的防护方式——数据库驱动会把元组里的值当成纯数据，不会解释成 SQL 关键字。这是每个写数据库代码的人必须牢记的习惯。

块 3：工具注册（同 char02 带参工具模式）

tools = [
    {"type": "function", "function": {
        "name": "add_employee",
        "description": "添加一名员工信息，需要姓名、可选部门和职务",
        "parameters": {"type": "object", "properties": {
            "name": {"type": "string", "description": "员工姓名"},        # required
            "department": {"type": "string", "description": "所属部门"},  # 可选
            "title": {"type": "string", "description": "职务"}
        }, "required": ["name"]}}                                        # 只有 name 必填
    }},
    {"type": "function", "function": {
        "name": "query_employee",
        "description": "查询员工信息，可按姓名精确查询；不传姓名则返回全部员工",
        "parameters": {"type": "object", "properties": {
            "name": {"type": "string", "description": "员工姓名（可选）"}  # 全可选
        }}}
    }},
]

注意 required 字段的设计：add_employee 只有 name 必填，department 和 title 可选——模型在用户只说"添加王小明"时也能正确调用（后两个参数用默认空字符串）。query_employee 的 name 全可选——模型在用户说"看所有员工"时会自动传空字符串或不传。

八、SQLite vs 其他数据库：什么时候用什么

数据库适用场景不适用场景
SQLite（本篇）单机小数据、桌面应用、嵌入式、原型开发、离线数据多用户并发、大数据量（>几GB）、写操作密集
MySQL / PostgreSQLWeb 应用、多用户并发、中等数据量单机离线、嵌入式
Redis缓存、会话、排行榜结构化数据持久化

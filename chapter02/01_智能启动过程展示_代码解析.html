位置：AI Agent Development Code/aiTest/char02 | 教学主题：智能体系统组成结构与运行机制 | 技术栈：dashscope function calling | 已验证可运行（2 轮工具调用全部正确）

一、这段代码要做什么

实现一个系统智能体的"开机自检"场景：模拟 Agent 启动时需要完成的一系列初始化动作，并通过两轮用户对话演示智能体如何自主决定调用哪个工具。这是整个 char02 章节的"入门篇"——02 篇讲状态追踪，01 篇讲智能体的"基本骨架"。

五个教学目标（全部在代码中实现）
  • 模型加载：配置 API Key + 指定模型名（qwen-plus）
  • 工具注册：把两个函数（取时间 / 系统检查）注册成可被模型调用的工具
  • 系统提示词配置：告诉模型"你是谁、该做什么"
  • 初始化记忆注入：首轮对话时把 system 提示词塞进 messages
  • 多轮日志追踪 + 函数调用工具调度：Agent 循环 + logging

二、原教材代码的问题

原代码使用的是虚构 API，无法运行

原文件导入的 qwen_agent.Agent / Tool / ChatMessage / QwenLLM / CompletionConfig / BaseTool 在真实的 qwen-agent 包里全部不存在（已实测 ImportError）。这是 char02 两篇的共同问题——教材臆造了一套不存在的框架 API。

三、整体流程图

run_startup_sequence() 启动
  │
  ├─ build_agent() 构建 config（模型名 / temperature / max_tokens / system_message）
  │
  ├─ 第1轮：agent_chat(config, "请执行一次系统检查", memory=None)
  │     │
  │     ├─ memory 初始化为 [system_message] + [user_input]
  │     │
  │     └─ while True 循环（Agent 循环的核心！）
  │           │
  │           ├─ dashscope.Generation.call(..., tools=tools)
  │           │     │
  │           │     ├─ 返回 tool_calls（模型说："我要调 startup_check"）
  │           │     │     │
  │           │     │     ├─ tool_registry["startup_check"]()  ← 本地执行
  │           │     │     │     返回 "系统初始化检查通过：..."
  │           │     │     │
  │           │     │     └─ 结果以 role=tool 追加到 memory → 继续循环
  │           │     │
  │           │     └─ 再调用一次模型 → 这次无 tool_calls → 返回最终回答
  │           │
  │           └─ 返回 (回复, 更新后的 memory)
  │
  ├─ 第2轮：agent_chat(config, "请告诉我现在几点", memory=上轮结果)
  │     │
  │     └─ 模型自主选择 get_current_time() 工具 → 执行 → 返回时间
  │
  └─ 打印两轮结果 + 查 agent_startup.log 看完整日志

四、核心概念速查表

概念代码中的实现一句话解释
工具注册表tool_registry = {"get_current_time": fn, ...}函数名 → 执行体的字典。模型只发指令，Python 负责执行
工具说明书tools = [{"type":"function", "function":{...}}, ...]给模型看的"工具目录"：有哪些工具、参数长什么样、干啥用
Agent 循环while True + tool_calls 判断模型可以连续调多个工具，直到它认为信息够了才给最终回答
初始化记忆注入memory = [{"role": "system", "content": system_message}]首轮对话时把 system 提示词塞进 messages 列表
多轮记忆传递每轮 agent_chat 返回更新后的 memory，下一轮传入让模型"记得"之前聊过什么
函数调用（Function Calling）dashscope.Generation.call(tools=tools) → response.output.choices[0].message.tool_calls模型不直接执行工具，只返回"调用指令"，本地解析后执行

块 3：工具注册（第 36-74 行，本文件最核心的改写）

# 可执行函数（本地 Python 负责"做事"）
def get_current_time() -> str:
    now = datetime.datetime.now()
    return now.strftime("当前时间是：%Y年%m月%d日 %H:%M:%S")

def startup_check() -> str:
    checks = ["模型加载完成", "工具已注册", "Memory注入成功", "上下文初始化完成"]
    return "系统初始化检查通过：" + "，".join(checks)

# 注册表：模型只发工具名，Python 查这里执行
tool_registry = {"get_current_time": get_current_time, "startup_check": startup_check}

# 说明书：给模型看的"工具目录"
tools = [
    {"type": "function", "function": {
        "name": "get_current_time",
        "description": "获取当前系统时间",
        "parameters": {"type": "object", "properties": {}}    # 空参数，因为这两个工具都不需要输入
    }},
    {"type": "function", "function": {
        "name": "startup_check", "description": "执行Agent启动时的系统检查任务",
        "parameters": {"type": "object", "properties": {}}
    }}
]
工具注册 = 两部分（新人最容易只做一半）

函数体（Python 执行）+ 说明书（模型理解），缺一不可。原写法把两部分合并在一个 BaseTool 子类里（run 是函数体，description/parameters 是说明书）；改写后拆成独立的函数 + tools 列表 + tool_registry 字典——更清晰，学生能看到"注册"到底做了什么。

块 4：build_agent（第 76-89 行）

def build_agent():
    logging.info("启动Agent构建流程")
    config = {
        "name": "SystemStartupAgent",
        "model": "qwen-plus",           # 模型加载
        "temperature": 0.3,             # 低随机性，启动仪式感不要太跳
        "max_tokens": 512,
        "system_message": "你是一位系统智能体助手，负责初始化流程、工具检查与运行日志监控。"
    }
    logging.info("Agent构建完成")
    return config

原写法用虚构的 Agent(name=..., llm=..., tools=..., system_message=...) 拼装；改写后用 config 字典承接——因为 agent_chat 函数本身已经是"智能体对象"，config 只是它的参数，不需要再包一层。

块 5：agent_chat 循环（第 91-143 行，本文件的灵魂）

def agent_chat(config, user_input, memory=None):
    # 1. 初始化记忆注入
    if memory is None:
        memory = [{"role": "system", "content": config["system_message"]}]
    memory = memory + [{"role": "user", "content": user_input}]

    # 2. Agent 循环：while True + tool_calls 判断
    while True:
        response = dashscope.Generation.call(
            model=config["model"], messages=memory, tools=tools,
            temperature=config["temperature"], max_tokens=config["max_tokens"],
            result_format='message'
        )
        message = response.output.choices[0].message
        tool_calls = getattr(message, 'tool_calls', None)

        # 3a. 无工具调用 → 返回最终回答
        if not tool_calls:
            reply = message.content
            memory = memory + [{"role": "assistant", "content": reply}]
            return reply, memory

        # 3b. 有工具调用 → 本地执行，结果回传给模型继续循环
        memory = memory + [message]
        for call in tool_calls:
            fn_name = call['function']['name']       # 注意：dashscope 返回 dict
            fn = tool_registry.get(fn_name)
            tool_result = fn() if fn else f"未注册: {fn_name}"
            memory = memory + [{"role": "tool", "content": tool_result, ...}]
三、新人必须理解的 while True 循环逻辑

这是智能体和普通对话程序的本质区别。普通对话：if 要调工具 → 调一次 → 结束。智能体：while True → 模型说调就调，调完再问模型要不要继续 → 直到模型说"不用了，我直接回答"。决策权在模型，执行权在本地。

块 6：启动测试（第 145-161 行）

def run_startup_sequence():
    config = build_agent()
    memory = None  # 首轮传 None → agent_chat 内部注入 system_message

    res1, memory = agent_chat(config, "请执行一次系统检查", memory)
    print(">> 系统检查响应：", res1)

    res2, memory = agent_chat(config, "请告诉我现在几点", memory)
    print(">> 当前时间响应：", res2)

两轮对话，每轮都把更新后的 memory 传给下一轮——多轮记忆的实现方式。第一轮 memory=None（首轮），第二轮 memory=第一轮结束后的列表（含 system + user1 + tool_call + tool_result + assistant1）。

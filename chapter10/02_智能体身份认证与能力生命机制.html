本次改写的核心：教材原版是 AgentRegistry + token/signature + capabilities 列表的简化版注册中心，本次按 A2A v1.0 规范升级为 Agent Card + HTTP Bearer 认证 + skills 语义匹配。原代码全部注释保留。

一、教材简化 vs A2A v1.0 规范的五维度差异

维度教材简化版（已注释保留）A2A v1.0 规范版（本次改写）
注册机制AgentRegistry.register_agent(name, token, signature, capabilities)Agent Card（/.well-known/agent.json）自动发现
认证方式token + signature 两个字段硬比对HTTP Authorization（Bearer / Basic / ApiKey / JWT）
能力声明capabilities: ["text_summary", "translate_text"]（纯列表）skills 对象（id + description + tags + inputModes + outputModes）
能力匹配registry.has_capability(name, task)（手动 if/elif）自动发现 + 语义匹配（registry.discover_by_skill / match_skill）
安全校验token + signature 同时比对Bearer token 校验（生产用 JWT / 非对称签名）
教材简化版的两个认证字段完全不符合真实 A2A 规范——真实协议里没有 token + signature 这种组合，只有 HTTP Authorization 头（Bearer / Basic / ApiKey / JWT）。signature 是生产级非对称签名认证才有的概念，简化版不该提前引入。

二、A2A v1.0 Agent Card 中的认证 + 能力组件

2.1 authentication —— 认证声明（A2A v1.0 § Agent Card）

{
  "authentication": {
    "schemes": ["bearer"],                        # 支持的认证方案
    "credentials": "Bearer A2A_DEMO_TOKEN"       # 生产不应嵌入 Card；教学演示
  }
}

# A2A v1.0 支持的四种认证方案（OpenAPI 风格）：
#   bearer  → Bearer token（JWT / 随机字符串）
#   basic   → HTTP Basic Auth（用户名+密码 Base64）
#   apiKey  → API Key（查询参数 / 自定义头）
#   oauth2  → OAuth 2.0（生产级推荐）

2.2 skills —— 能力声明（A2A v1.0 § Skill）

# 教材简化版：纯字符串列表
capabilities: ["text_summary", "translate_text"]

# A2A v1.0：结构化 Skill 对象
skills: [
  {
    "id": "text_summary",
    "description": "对长文本进行压缩摘要",       # 语义描述（客户端可基于此匹配）
    "tags": ["nlp", "summary", "text"],          # 标签（辅助匹配）
    "inputModes": ["text"],                      # 支持输入类型
    "outputModes": ["text"]                      # 支持输出类型
  },
  {
    "id": "translate_text",
    "description": "多语言文本翻译",
    "tags": ["nlp", "translate", "language"],
    "inputModes": ["text"],
    "outputModes": ["text"]
  }
]
Skill vs capability 的本质区别：教材用 capability 列表做"有/没有"的硬判断；A2A 的 Skill 对象让客户端可以基于 description + tags 做语义匹配——"帮我总结一下这段文字"能自动匹配到 text_summary skill，而不需要写死关键词。

        self._skill_ids = {s["id"] for s in skills}

    def verify_auth(self, auth_header) -> bool:
        """校验 HTTP Authorization 头（A2A 标准）"""
        # "Bearer " → 提取 token 比对
        parts = auth_header.split(" ", 1)
        return parts[0].lower() == "bearer" and parts[1] == self.server_token

                return skill["id"]

3.2 A2ARegistry —— 按 Agent Card 自动发现

class A2ARegistry:
    def register(self, server: A2AServer):
        """等价于 Agent 在 /.well-known/agent.json 发布 Card"""
        self._agents[server.name] = server

    def discover_by_skill(self, skill_keyword) -> List[A2AServer]:
        """按 skill 关键词自动找到合适的 Agent"""
        for server in self._agents.values():
            for skill in server.agent_card["skills"]:
                if skill_keyword.lower() in (skill["id"] + skill["description"]).lower():
                    return server

七、动手练习

  1. 加 JWT 认证：把 Bearer token 换成 PyJWT 签名验证——Agent Card 的 authentication.schemes 改成 ["jwt"]，verify_auth 用 pyjwt.decode 验签。
  2. 加 404 error 码：让 A2ARegistry.discover_by_skill 返回空列表时，客户端返回 error -32002 的增强版（data 里列所有可用 Agent）。
  3. 加 Agent Card HTTP 端点：用 Flask/FastAPI 暴露 /.well-known/agent.json，让客户端可以通过 HTTP GET 自动发现——这就是 A2A 发现机制的真实形态。
  4. 对接真实 a2a-sdk：pip install a2a-sdk，把 A2AServer 改成真实 HTTP 服务端，用官方 SDK 搭建完整的 A2A 通信链路。

八、总结

本次改写把 char10-02 从"简化版注册中心 + 硬编码 token/signature"升级为按 A2A Protocol v1.0 规范完整实现的认证 + 能力声明系统。核心变化有五：

  1. 注册机制：AgentRegistry.register → A2ARegistry（按 Agent Card 自动发现）
  2. 认证方式：token + signature 硬比对 → HTTP Bearer token（A2A 标准）
  3. 能力声明：capabilities 纯列表 → skills 对象（含 description/tags）
  4. 能力匹配：if/elif 硬编码 → match_skill 三级自动匹配 + discover_by_skill 自动发现
  5. 错误处理：自然语言字符串 → A2A 标准 JSON-RPC error 码（-32001 认证失败 / -32002 能力不匹配）

两个关键设计思想值得记住：

  • Agent Card 是"身份证 + 简历 + 岗位说明"三合一——客户端拿到 Card 就知道"这是谁、能干嘛、怎么调用、用什么认证"
  • 认证失败和能力不匹配是两种不同的错误——-32001 告诉你"你是谁我不认识"，-32002 告诉你"我认识你但你要的活我干不了"

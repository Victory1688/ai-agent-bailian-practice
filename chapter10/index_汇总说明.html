二、六层架构速览

L6 编排组合层（06 协商竞标）

把所有组件组合成完整多 Agent 系统：A2ANegotiationOrchestrator + BidderRegistry + skills 匹配评分 + dashscope 辅助评标。

L5 通信模式层（04 / 05）

两种核心通信范式：04 Request-Response（一对一，JSON-RPC Request→Response）+ 05 Pub/Sub（一对多，Notification 无 id + subscribeToTask + SSE）。

L4 核心能力层（02 / 03）

Agent 能证明自己是谁 + 能干什么：02 Agent Card skills 三级匹配 + Bearer Token 认证；03 MCPServer Tools/Resources 三原语。

L3 业务对象层（01）

A2A 协议定义的核心数据模型：Message(role+parts+contextId) + Part(text/file/data) + Task(七态) + Artifact + Agent Card。

L2 协议信封层（01-06 共用）

JSON-RPC 2.0：Request（有 id，期望 Response）/ Notification（无 id，单向）/ Response（result 或 error）。A2A 和 MCP 共用！

L1 传输层

怎么送过去：HTTP / SSE（text/event-stream）/ gRPC / HTTP-REST / STDIO（MCP 本地）。规范兼容多传输。

四、A2A vs MCP 关系（关键理解点）

为什么两个协议都需要？它们解决完全不同的问题：

维度A2A (Agent↔Agent)MCP (Agent↔Tool/Resource)
通信对象Agent 和 AgentAgent 和 Tool
核心对象Agent Card / Task / Message / ArtifactTool(inputSchema) / Resource(uri) / Prompt
协议信封共用 JSON-RPC 2.0
传输层HTTP(SSE) / gRPC / RESTSTDIO / HTTP(SSE) / Streamable HTTP
适用场景"谁来干这个活？"（多 Agent 协商/竞标）"我需要什么数据？"（查数据库/调 API/读文件）
教材简化把 type 字段手写分 request/response概念误解：把三段 prompt 叫"MCP 格式"

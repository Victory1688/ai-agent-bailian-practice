例 10-3 讲解：A2A 与 MCP 协议联动开发

本节关键发现：教材对 MCP 协议存在概念性误解——它把 [system, user, memory] 三段式 prompt 叫"MCP 格式"，但真实 MCP (Model Context Protocol) 根本不是 prompt 格式协议，而是 Agent 调 Tool/Resource 的通信协议。A2A 和 MCP 组合才是完整的多 Agent 通信基础设施。

一、本节要解决什么问题

例 10-1 讲了 A2A 消息格式，例 10-2 讲了 A2A 认证与能力匹配，这一篇（10-3）讲的是：当一个 Agent 需要干活时，它怎么调用外部工具、怎么查外部数据。

教材原版用虚构的 qwen_agent 框架，在 ContextAwareAgent.handle_message() 里手动拼了一个 [system, user, memory] 三段式 prompt，然后把这叫"MCP 格式"。这种实现方式在真实世界里站不住脚——因为 MCP 协议根本不是这样的。

所以本次改写的核心目标是：

  1. 用真实的 A2A 协议（JSON-RPC 信封 + Agent Card + Task 生命周期）完成 Agent-to-Agent 通信
  2. 用真实的 MCP 协议（Tools / Resources / Prompts 三原语 + JSON-RPC 方法 tools/list / tools/call / resources/read）完成 Agent-to-Tool 调用
  3. 把两者组合起来：A2A 管"谁干什么"，MCP 管"用什么工具干"，形成完整闭环

二、A2A 与 MCP 的关系（核心概念辨析）

为什么两个协议都需要？

这两个协议名字像，但设计目标完全不同，它们解决的是多 Agent 系统的两个不同层面：

维度A2A (Agent-to-Agent Protocol)MCP (Model Context Protocol)
发起人Google / Linux Foundation（2025.04）Anthropic（2024.11 发布）
解决什么Agent ↔ Agent 通信Agent ↔ Tool/Resource 通信
一句话总结"谁能干什么，怎么找到它""能干什么工具，怎么调用它"
核心对象Agent Card / Task / Message / ArtifactTool / Resource / Prompt（三原语）
JSON-RPC 方法message.send / tasks/gettools/list / tools/call / resources/read
传输层HTTP(SSE) / gRPC / RESTSTDIO / HTTP(SSE) / Streamable HTTP
类比公司内部"谁负责什么"的组织架构员工可用的"工具/数据库/文档"清单
A2A + MCP 组合的完整链路：

1A2A message.send —— Agent A 给 Agent B 发任务
2MCP tools/list —— Agent B 发现自己能用的工具
3MCP tools/call —— Agent B 调用工具获取数据
4MCP resources/read —— Agent B 读取静态资源
5dashscope.Generation.call —— Agent B 整合 MCP 结果生成最终响应
6A2A Task —— Agent B 返回任务结果（completed + Artifact）

三、改写后的系统架构

A2AMCPOrchestrator（主控调度）
├── A2A Layer ── Agent-to-Agent 通信
│   └── A2AServer (agent:finance)
│       ├── agent_card（Agent Card v1.0 规范）
│       ├── verify_auth()（Bearer token）
│       ├── message_send()（核心：收任务 → 调 MCP → LLM 生成）
│       └── _task_registry（Task 生命周期）
│
└── MCP Layer ── Agent-to-Tool 通信
    └── MCPServer (mcp:financial)
        ├── tools/list（返回 3 个工具 + inputSchema）
        ├── tools/call（执行指定工具）
        ├── resources/list（返回静态资源列表）
        ├── resources/read（读取 World Bank GDP CSV）
        └── tool_handlers（get_gdp_data / search_news / cpi_impact）

关键设计：A2AServer 绑定一个 MCPServer——Agent 不自己实现业务逻辑，而是把任务委托给 MCP Server 的 Tools/Resources。这就是两个协议组合的真正价值：A2A 管"谁"，MCP 管"工具"。

四、MCP 层核心组件（MCPServer）

MCP 协议的三个原语对应规范 § Core Concepts，本次改写实现了前两个：

① Tools（可执行函数）

按 MCP v2025-03-26 规范，Tool 对象必须包含 name + description + inputSchema（JSON Schema 格式）：

{
  "name": "get_gdp_data",
  "description": "获取指定国家 GDP 增长率数据（模拟）",
  "inputSchema": {
    "type": "object",
    "properties": {
      "country": { "type": "string", "description": "国家名称" },
      "year": { "type": "integer", "description": "年份" }
    },
    "required": ["country", "year"]
  }
}

Agent 通过 tools/list 发现所有可用工具，通过 tools/call(name, arguments) 执行——返回结果必须是 ToolResult 格式（含 content: [{type: "text", text: "..."}] + isError: boolean）。

② Resources（数据源）

Resources 是可读取的静态数据，用 URI 标识（如 world-bank://country/gdp-forecast）。Agent 通过 resources/list 发现，通过 resources/read(uri) 读取——返回 contents: [{uri, mimeType, text}]。

③ Prompts（模板，占位）

教材原版把三段式 prompt 叫"MCP 格式"，但在真实 MCP 规范里，Prompt 是第三个原语——可复用的模板，通过 prompts/list / prompts/get 协议方法管理。本次演示暂不实现。

五、完整交互流程（运行时实际发生了什么）

Step 1-2：MCP Server 初始化 + A2A Agent 注册

create_financial_mcp_server() 构建 MCPServer，含 3 个 Tool + 1 个 Resource。然后创建 A2AServer(agent:finance) 并 绑定 MCP Server——这是关键绑定关系，决定了 Agent 能调哪些工具。

Step 3：Orchestrator 启动

A2AMCPOrchestrator 同时注册 A2A Agent 和 MCP Server，维护两个独立注册表。

Step 4：MCP tools/list（Agent 发现自己能用啥）

Orchestrator 调用 mcp_list_tools("mcp:financial")，MCPServer 返回完整 Tool 列表（含 inputSchema）。这是 MCP 协议的自动发现能力——Agent 不需要硬编码工具列表。

Step 5：完整 A2A + MCP 交互（6 步）

# A2A Agent 收到任务后，内部执行：

# Step 5.1 — MCP 发现
available_tools = self.mcp.tools_list()["tools"]
# → ['get_gdp_data', 'search_economic_news', 'calculate_cpi_impact']

# Step 5.2 — MCP 调用 1：查 GDP
call_result = self.mcp.tools_call("get_gdp_data", {"country": "中国", "year": 2024})
# → 中国 2024 GDP 增长率: 5.0%

# Step 5.3 — MCP 调用 2：查通胀新闻
call_result = self.mcp.tools_call("search_economic_news", {"keyword": "通胀"})
# → 2024 年 CPI 持续回落至 0.2%，通胀压力基本消除

# Step 5.4 — MCP 读取：World Bank GDP 预测
wb_data = self.mcp.resources_read("world-bank://country/gdp-forecast")
# → 中国,5.0 / 美国,2.5 / 欧盟,1.2 / 日本,0.8 / 印度,6.5

# Step 5.5 — dashscope 整合 MCP 结果生成最终分析
response = dashscope.Generation.call(model="qwen-plus", ...)

# Step 5.6 — 返回 A2A Task（completed + Artifact）
return {"status": {"state": "completed", ...}, "artifacts": [...]}

九、动手练习

  1. 加一个 Tool：在 create_financial_mcp_server() 里新增 get_interest_rate 工具（返回央行 LPR 数据），看看 A2AServer 能否自动发现并调用它——你需要在 message_send() 里加一个触发条件。
  2. 加一个 Resource：添加一个 central-bank://policy-meetings Resource，里面存历年货币政策会议纪要片段，让 LLM 把这些历史信息也整合进分析。
  3. 加第二个 A2A Agent：创建一个 agent:tech（绑定 Tech MCP Server），支持分析科技行业趋势。然后让 agent:finance 也能通过 A2A 调用 agent:tech——这就是 Agent-to-Agent + Agent-to-Tool 的两层协作。
  4. 改 Agent 意图路由：当前 Agent 用 if/elif 硬编码选工具。把它改成让 dashscope 先做一次 function calling 或意图识别，再决定调哪些 MCP Tool——这样 Agent 就"真的聪明"了。

例 10-6 讲解：多智能体协商与竞标系统

本节核心概念：当多个 Agent 都能完成同一 Task 时，怎么选？教材用 random.uniform 模拟评分，真实 A2A 协议组合了 Pub/Sub 广播（例 10-5） + message.send 投标（例 10-4） + Agent Card skills 匹配（例 10-2），形成"广播 → 投标 → 评标"三阶段协商闭环。A2A 协议本身没有专门的"竞标"方法，但所有基本组件在 01-05 篇里都已经有了。

一、本节要解决什么问题

前面 5 篇讲的都是"一对一"通信：要么 Request-Response（A → B），要么 Pub/Sub（Publisher 广播给 Subscribers，但 Subscriber 不发投标回来）。到这一篇，我们要解决：

多个 Agent 都有能力干同一件事，选谁？怎么选？

教材原版的问题：

  • CompetitiveAgent.evaluate_score() 用 random.uniform(-0.3, 0.3) 模拟评分——完全随机，Agent 根本不知道自己能不能干这个活
  • TaskOrchestrator.dispatch_task() 里用 for agent in self.agents: agent.bid_for_task() 拉模式——Orchestrator 主动拉每个 Agent，Agent 被动响应
  • 虚构框架 qwen_agent.Agent 拼三段 prompt

本次改写的核心目标：用真实 A2A v1.0 协议组合出完整的协商-竞标闭环，Agent 主动评估自己能不能干（Agent Card skills 匹配），Orchestrator 用 Pub/Sub 广播 Task 让 Agent 主动投标。

四、3 个投标 Agent 的 Agent Card skills 设计

这是 Agent 能力声明的核心（A2A 规范 § Agent Card → skills）。三个 Agent 各有不同专长，Task 是"人民币汇率波动对外贸企业的影响"——谁的 skills 匹配度最高？

BidderAgentskillsTask 关键词匹配match_score
agent:qwen_finance macro_analysis（宏观经济） + exchange_rate（汇率波动） "汇率" → tags 匹配 ✓
"外贸" → exchange_rate description ✓		 1.00
agent:coze_sentiment sentiment（舆情解读） + risk_analysis（风险评估） "波动" → risk_analysis ✓
"影响" → 部分匹配		 1.00
agent:deepseek_data data_mining（数据挖掘） + trade_analysis（外贸数据） "外贸" → trade_analysis tags ✓
"汇率" → 无匹配 ✗		 0.50

最终评分公式：combined_score = base_capability × (0.5 + 0.5 × match_score)

• qwen_finance: 8.7 × (0.5 + 0.5 × 1.0) = 8.70
• coze_sentiment: 8.6 × (0.5 + 0.5 × 1.0) = 8.60
• deepseek_data: 8.4 × (0.5 + 0.5 × 0.5) = 6.30（匹配度低 → 分数大幅下降）

五、完整 4 步协商流程

1Orchestrator 创建 Task + 广播 submitted
  {"jsonrpc","2.0", method:"task.submitted", params:{taskId, description}}
2每个 BidderAgent 收到广播 → match_skill() → score
  match >= 阈值 → generate_bid_proposal(dashscope) → create_bid()
  match < 阈值 → 主动放弃不投标
3Orchestrator 收集所有投标 → _evaluate_bids()
  默认按 score 降序 → 可选 dashscope 辅助综合评审
4Orchestrator 广播 task.winner Notification
  中标者收到 → 开始执行 Task（返回 Artifact）

2 agent:coze_sentiment — score=8.6, match=1.00
（方案概要：基于 risk_analysis 专长，聚焦企业风控视角，分析汇率波动风险敞口...）
3 agent:deepseek_data — score=6.3, match=0.50
（方案概要：基于 data_mining + trade_analysis，侧重外贸历史数据挖掘分析...）

dashscope 辅助评标意见

LLM 评标："综合评估：Qwen Finance 得分最高且匹配度满分。推荐最优投标者编号：[1]"

关键验证点

  • skills 匹配正确：deepseek_data 只有 trade_analysis 一个 skill 匹配（"外贸"），所以 match_score=0.50，综合分被大幅拉低
  • 中标合理：qwen_finance 的两个 skills（macro_analysis + exchange_rate）都完美覆盖 Task，LLM 评标也确认它最优
  • 所有 Agent 真实调用了 dashscope：每个投标方案都是 qwen-plus 实时生成的，不是硬编码

八、动手练习

  1. 加 Agent 主动放弃：当前所有 Agent 都投标（match_score >= 0.25）。把阈值调高到 0.7，再看 deepseek_data（match=0.50）会不会放弃投标——这就是"Agent 有自知之明"的真实体现。
  2. 加多 Task 并行协商：Orchestrator 同时广播 2 个 Task，看 3 个 Agent 会不会对每个 Task 独立评估、独立投标。可以让不同 Task 匹配不同 Agent。
  3. 加中标者执行阶段：当前中标后只打印结果。让 Orchestrator 把 Task 真正交给中标 Agent，中标 Agent 用 dashscope 执行完整分析并返回 Artifact（例 10-3 的 MCP + LLM 模式）。
  4. 加多轮协商：第一轮中标者如果无法满足所有需求（比如缺少某些 resources），Orchestrator 发起第二轮协商让剩余 Agent 重新投标——这就是真实世界"谈判"的过程。

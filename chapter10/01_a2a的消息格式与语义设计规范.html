一、A2A 协议是什么

A2A (Agent2Agent Protocol) 是 Google 2025 年 4 月发起、捐赠给 Linux Foundation 的开放标准，让不同框架（LangGraph / CrewAI / Google ADK / Genkit 等）构建的 AI Agent 能够：

  1. 自动发现：通过 Agent Card（/.well-known/agent.json）暴露能力，客户端自动找到可交互的 Agent
  2. 标准化协作：用 JSON-RPC 2.0 消息格式交换 Task / Message / Artifact
  3. 跨进程互通：传输层支持 HTTP(SSE 流式) / gRPC / HTTP/REST
  4. 企业级安全：OpenAPI 风格的认证声明，JWT / API Key 等多种方案

重要边界：A2A 覆盖 Agent-to-Agent 通信；MCP（Model Context Protocol）覆盖 Agent-to-Tool 通信——两者互补。

二、教材简化 vs 真实 A2A v1.0 的五维度差异

维度教材简化版（已注释保留）真实 A2A v1.0（本次改写实现）
消息信封自定义 8 字段 dict（id/timestamp/from/to/type/intent/context_id/payload/auth）JSON-RPC 2.0 标准信封（jsonrpc/id/method/params → result/error）

三、本次改写实现的 A2A v1.0 核心对象

3.1 Agent Card —— Agent 的"数字名片"

{
  "name": "agent:executor",
  "description": "执行财经分析任务的智能体",
  "endpoint": "http://localhost:8080/a2a",
  "capabilities": {
    "streaming": false,           # 是否支持 SSE 流式推送
    "pushNotifications": false,   # 是否支持异步回调
    "stateTransitionHistory": false
  },
  "skills": [
    {"id": "analyze_financial_trends", "description": "分析经济趋势与通胀风险"},
    {"id": "generate_report", "description": "生成财经分析报告"}
  ],
  "authentication": {
    "schemes": ["bearer"],
    "credentials": "Bearer A2A_DEMO_TOKEN"
  }
}

Agent Card 通常发布在 /.well-known/agent.json 路径——类似 robots.txt 的约定，让客户端可以自动发现 Agent 的能力。

3.2 JSON-RPC 2.0 消息信封

# 请求
{
  "jsonrpc": "2.0",                    # 固定值
  "id": "req-demo-001",                # 请求 ID（客户端生成，匹配响应）
  "method": "message.send",            # A2A 规范方法名
  "params": {
    "message": { ... },                 # A2A Message 对象
    "configuration": {"historyLength": 10}
  }
}

# 响应（Task 已简化）
{
  "jsonrpc": "2.0",
  "id": "req-demo-001",                # 匹配请求 ID
  "result": {
    "id": "task-abc123",
    "contextId": "ctx-def456",
    "status": {"state": "completed"},
    "kind": "task"                      # "task" 或 "message"
  }
}

3.3 Message + Part —— 消息结构

{
  "messageId": "msg-user-abc123",
  "role": "user",                       # "user" 或 "agent"
  "contextId": "ctx-conversation-abc",  # 服务端生成，关联多轮交互
  "referenceTaskIds": ["task-abc123"],  # 可选：引用之前 Task 进行细化
  "parts": [
    {"kind": "text", "text": "请基于刚才的分析重点关注通胀风险"}
  ]
}

# Part 支持三种 kind：
# {"kind": "text", "text": "..."}                          ← 文本
# {"kind": "file", "file": {"name": "...", "mimeType": "...", "bytes": "..."}}  ← 文件
# {"kind": "data", "data": {"schema": {...}, "bytes": "..."}}  ← 结构化数据

3.4 Task —— 有状态工作单元

{
  "id": "task-abc123",
  "contextId": "ctx-conversation-abc",
  "status": {
    "state": "completed",               # submitted / working / input-required / completed / canceled / rejected / failed
    "message": {"role": "agent", "parts": [{"kind": "text", "text": "处理完成"}]}
  },
  "artifacts": [
    {
      "artifactId": "art-def456",
      "name": "agent_executor_response",
      "description": "财经分析结果",
      "parts": [{"kind": "text", "text": "分析完成：Asia 地区..."}]
    }
  ],
  "history": [ /* 本次交互的所有 Message 历史 */ ],
  "kind": "task"
}

3.5 contextId + referenceTaskIds —— 多轮协作胶水

字段谁生成作用教材简化版对应
contextId服务端（A2A Server）关联同一次协作的所有 Task 和 Messagecontext_id（手动传 uuid4）
referenceTaskIds客户端引用之前的 Task 进行细化/追问——（教材完全没有）

关键设计：contextId 由服务端生成，不是客户端——这保证了"谁是这次协作的权威管理者"，防止客户端伪造 contextId 串联不属于同一次协作的消息。

五、A2A v1.0 核心 API 方法（本次实现覆盖）

六、A2A vs MCP：互补关系

维度A2A (Agent2Agent)MCP (Model Context Protocol)

解决什么多 Agent 协作时的互通Agent 调用外部工具/数据源的标准化
发布者Google → Linux FoundationAnthropic → Model Context Protocol Foundation
核心对象Agent Card / Task / Message / ArtifactTool / Resource / Prompt
传输层JSON-RPC 2.0 over HTTP/SSE/gRPCJSON-RPC 2.0 over stdio / HTTP/SSE
教材位置char10-01（本篇）char07-01（虚构简化版 MCP 字段）
一句话记忆：A2A 让两个 Agent "说同一种语言"，MCP 让一个 Agent "能用所有工具"——两者组合就是完整的多 Agent 系统通信基础设施。

八、总结

本次改写把 char10-01 从"自定义 8 字段简化版"升级为按 A2A Protocol v1.0 官方规范完整实现。核心变化有五：

  1. 消息信封：自定义 dict → JSON-RPC 2.0 标准信封
  2. 发现机制：手动 register() → Agent Card（/.well-known/agent.json）
  3. 消息结构：intent + payload → Message + Part（role / messageId / parts: text/file/data）
  4. 任务模型：返回字符串 → Task 对象 + 完整生命周期 + Artifact
  5. 多轮协作：手动 context_id → 服务端生成 contextId + referenceTaskIds 细化

生产级 A2A 协议还包含 Streaming SSE 推送、Push Notifications、gRPC 传输、多租户隔离等组件，本次改写省略了需要 HTTP 服务才能运行的部分，但所有消息格式和对象结构严格遵循 A2A v1.0 JSON Schema——把同进程实现换成 HTTP 端点就是可直接上线的 A2A Server。

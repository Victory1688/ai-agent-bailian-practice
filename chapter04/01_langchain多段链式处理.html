对应文件：char04/01_langchain多段链式处理.py | 教材出处：第4章【例4-1】Chains 链式构造器 | 生成日期：2026-10-11

一、这份代码整体在做什么（一段话讲给新人）

这份代码演示了 LangChain 的链式构造器（Chains）：把一个复杂任务——"研究人工智能伦理的社会意义"——拆成三个有序的小步骤，让模型像流水线一样逐步加工：

  1. 子链一：给一个主题 → 列出 3 个细分研究方向（子主题）
  2. 子链二：拿着子主题 → 为每个方向提出一个有挑战性的研究问题
  3. 子链三：拿着研究问题 → 分析它们对社会发展的意义

三段用 SequentialChain 串成一条流水线，上一段的输出自动作为下一段的输入——这就是"链式处理"的本质：任务拆解 + 结果接力。学完这份代码，你就掌握了"多步骤任务自动化"的最基本骨架。

二、原教材代码为什么跑不起来（三类问题）

问题原写法说明
1. import 路径断裂from langchain.llms import OpenAI 等 3 行LangChain 1.x 拆分了模块路径：PromptTemplate 搬进 langchain_core.prompts；经典链 LLMChain/SequentialChain 收纳进 langchain_classic.chains；langchain.llms.OpenAI 类已被移除
2. 模型不可直连llm = OpenAI(temperature=0.5)OpenAI 类需要 OPENAI_API_KEY 且国内无法直连官方服务——改用百炼平台的 ChatTongyi（qwen-plus）
3. 原代码隐藏 bugfull_chain.run(topic=...)run() 只支持"恰好一个输出键"的链，而 SequentialChain 声明了 3 个输出变量——即使在 0.x 旧版同样会抛 ValueError。这不是版本迁移问题，是教材代码本身的错误
改写策略：两改两不动
  • 改：import 路径（3 行）+ 模型类（OpenAI → ChatTongyi，temperature=0.5 语义不变）
  • 不动：三条子链的模板文本、变量定义、output_key 命名，以及 SequentialChain 的组装方式——链式拆解的思想是本篇灵魂，一字不丢
  • 修复：run() → invoke()（bug 修复 + 1.x 标准入口），并把三个输出全部打印出来，让"接力"效果可见

关键机制：变量接力是怎么自动发生的

每条子链声明 output_key（产物叫什么名），SequentialChain 把每个 output_key 的结果自动填充到下游链模板的同名占位符里——chain2 的模板里有 {subtopics}，chain1 的 output_key 恰好叫 subtopics。这就是为什么模板文本一个字都没改还能跑通：接线的规则写在变量名里。

四、核心概念速查表

概念是什么在本例中的角色
PromptTemplate提示词模板：占位符 + 填充规则定义每段任务的"话术"，input_variables 声明需要哪些变量
LLMChain最小链单元：模板 + 模型 = 一次完整调用三条子链的基本积木
output_key本链输出变量的命名给产物起名，供下游链的占位符引用
SequentialChain顺序组合器：按序执行多条链并自动传递变量把三段流水线串起来，声明全局输入/输出
input_variables / output_variables链的"总入口参数表"和"总交付物清单"topic 进，subtopics/questions/impact 出
verbose=True打印链的执行过程日志运行时输出 "Entering/Finished SequentialChain chain"
invoke()1.x 统一调用入口：传字典、回字典替代 run()，多输出键时唯一的正确姿势

五、逐段代码讲解

5.1 模型初始化（改写点）

llm = ChatTongyi(
    model="qwen-plus",
    temperature=0.5,
    dashscope_api_key=os.environ.get("DASHSCOPE_API_KEY"),
)

原代码 OpenAI(temperature=0.5) 只保留 temperature=0.5 语义，模型换成百炼 qwen-plus。API Key 从环境变量读取（不硬编码进源码）。ChatTongyi 与 OpenAI 类在 LangChain 中同属"模型接口"，对下游链完全透明——换模型不动链，这正是框架分层的价值。

5.2 三条子链（原样保留）

chain1 = LLMChain(llm=llm, prompt=prompt1, output_key="subtopics")
chain2 = LLMChain(llm=llm, prompt=prompt2, output_key="questions")
chain3 = LLMChain(llm=llm, prompt=prompt3, output_key="impact")

每条链三个要素：模型（llm）+ 模板（prompt）+ 产物命名（output_key）。注意三条链共用同一个 llm 实例——链是"调用配方"，模型是"灶台"，多个配方可以共用一个灶。

5.3 串成总链（原样保留）

full_chain = SequentialChain(
    chains=[chain1, chain2, chain3],
    input_variables=["topic"],
    output_variables=["subtopics", "questions", "impact"],
    verbose=True
)

input_variables 声明"这条流水线从外界要什么"（topic），output_variables 声明"交付什么"（三段产物全部保留，中间产物也可审查——调试流水线时这非常关键）。

5.4 执行与打印（bug 修复点）

result = full_chain.invoke({"topic": "人工智能伦理"})
print(result["subtopics"])   # 中间产物一：三个子主题
print(result["questions"])   # 中间产物二：三个研究问题
print(result["impact"])      # 最终产物：社会价值分析

invoke() 传入变量字典、返回变量字典——进出对称。三个键全部打印，让你亲眼看到"上一段产出喂给下一段"的接力证据。

七、经典链（本篇）vs LCEL 管道（char01-02）对比

char04-01 的 SequentialChain 和 char01-02 的 LCEL 管道（template | llm | parser）做的是同一件事——把多步调用串起来。两种写法对照：

维度经典链 SequentialChain（本篇）LCEL 管道（char01-02）
写法声明式：把链和变量名"登记"给组合器管道式：用 | 运算符把组件串起来
变量传递靠 output_key 与占位符同名匹配靠管道顺序（上一步输出 = 下一步输入）
多输出保留原生支持（output_variables 全留）需要用 RunnableParallel 等显式构造
状态LangChain 0.1.17 起标记废弃，2.0 将移除LangChain 1.x 的官方推荐
教学价值变量接力机制显式可见，适合建立心智模型更简洁、可组合任意 Runnable，是生产写法
为什么教材用"过时"的 SequentialChain 教学是有道理的

SequentialChain 把"变量怎么在链间流动"写成了显式的名字匹配——新人能看清每一滴数据的去向；LCEL 管道简洁但把传递机制藏进了 | 运算符。先学看得见的（本篇），再学更优雅的（char01-02），理解顺序上先本篇后 char01-02 反而更顺。

char04 在三章体系中的位置

char01 教"对模型说什么"（单次调用的提示词建模），char02 教"让模型做什么"（agent_chat 循环 + 工具），char03 教"把模型变成服务"。char04 开始引入框架：LangChain 把"提示词、模型、链、记忆、工具、Agent"标准化成组件——本篇是框架篇的第一块砖：用链组织任务流程。后面几篇会看到框架化的记忆、Agent 等组件。

八、生产视角：教学版离上线的差距

  • 无错误处理：三段链中任何一段模型调用失败（网络/限流）整条流水线崩掉——生产要加 try/except + 失败重试 + 断点续跑（记住已完成到哪一段）
  • 上下文膨胀无预算：子链三的输入 = 子链二的完整输出，任务更长时会逼近上下文窗口上限——生产要加中间结果压缩/摘要
  • 输出不校验：子链一要求"逗号分隔三个方向"，模型偶尔不守约则下游模板照样填充——生产要加输出解析校验 + 不合格重试
  • 串行无并发：三段严格串行总耗时 = 三次调用之和；若某几段相互独立（本例不相独立，但很多业务里存在）可用并行结构省时
  • deprecation 警告：LLMChain / run() 已标记废弃（2.0 移除）——迁移到 LCEL 是生产必答题（见动手练习 4）

九、动手练习

  1. 加一段链：在 chain3 之后追加 chain4（output_key="roadmap"），模板要求"基于上述意义，给出三个可落地的行动建议"。提示：记得把它加进 chains 列表和 output_variables。

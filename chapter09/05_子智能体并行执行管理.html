三、核心设计思想：并行执行的三个关键组件

3.1 threading.Thread：启动一个线程

t = threading.Thread(target=self.run_agent, args=(agent, name))
t.start()     # 启动线程（不阻塞，立刻返回）
threads.append(t)

Thread 的 target 参数是线程入口函数，args 是传给它的参数。start() 启动后主线程继续往下走，新线程在后台跑——这就是"并行"的含义。

3.2 threading.Lock：保护共享数据

self.lock = threading.Lock()

def run_agent(self, agent, name):
    result = agent.call("")
    with self.lock:              # 进入临界区
        self.results[name] = result
    # 退出 with 块时自动释放锁

self.results 是所有线程共享的字典——如果不加锁，两个线程可能同时执行 results[name] = result，导致数据丢失或字典内部状态损坏。with self.lock: 的含义是：同一时刻只有一个线程能进入这个代码块，其他线程必须等当前线程退出后才能进。

为什么结果字典需要锁？ Python 的 GIL（全局解释器锁）让单条字节码原子执行，但 dict[key] = value 不是单条字节码——它是"计算 hash → 检查 key 是否存在 → 写入值 → 更新字典大小"四步。如果两个线程同时写入，可能在"检查 key 是否存在"后都认为 key 不存在，然后各自写入——一个值会被覆盖。

3.3 Thread.join()：屏障等待

for t in threads:
    t.join()    # 主线程阻塞，等 t 线程结束后才继续

join() 是并行的"收口"——所有子线程都启动了，但主线程不能往下走（不能调 LLM 汇总），必须等最慢的那个线程也结束。这就是为什么总耗时等于最慢 Agent 的耗时（1.7s 的 TrendAgent），而不是三个相加。

五、Python 线程 vs 进程：为什么本篇用 Threading

维度threading（本篇）multiprocessing
内存共享同一进程内存（直接读写同一个 Dict）每个进程独立内存（需要 Queue/Pipe 传递数据）
开销线程创建/切换快（毫秒级）进程创建/切换慢（秒级）
GILCPU 密集型无法真正并行（GIL 锁死）绕过 GIL，真正多核并行
适用场景IO 密集型（sleep / 网络请求 / 文件读写）CPU 密集型（计算 / 图像处理）
为什么本篇用 Threading？三个子 Agent 的核心操作是 time.sleep()——这是 IO 密集型操作（CPU 闲着等）。Python 的 GIL 在 sleep/网络等待时会释放，所以多线程能真正并行。如果子 Agent 是 CPU 密集型计算（如大量数据处理），应该用 multiprocessing 才能真正加速。

六、跨章节对照：并行/串行/依赖的三维关系

组合代表执行方式耗时
串行 + 有依赖char09-01/02/04一个接一个，顺序固定所有任务耗时相加
并行 + 无依赖本篇 char09-05同时启动，各自跑完最慢那个的耗时
并行 + 有依赖char05 LangGraph 同层并行依赖先满足，同层无依赖的并行各层最慢耗时之和

char05 的 LangGraph 其实是"并行 + 有依赖"的框架化实现——它把"哪些节点可以并行"这件事自动算出来（拓扑排序后，同一层的节点可以同时跑），本篇是这个逻辑的手写最简版（假设所有 Agent 都无依赖，直接全并行）。

八、总结

本篇的核心资产是一个 30 行的 ParallelExecutor 类——它把并行执行拆成了三个清晰的组件：

  1. Thread.start()：同时启动所有子 Agent
  2. Lock 保护：多线程写共享字典时加锁，防止数据丢失
  3. Thread.join()：屏障等待，等最慢的那个也结束再往下走

实测加速比 2.59x（4.4s → 1.7s），接近理论最优。但并行加速有个前提：任务之间不能有依赖——如果 A 依赖 B 的输出，A 再闲也得等 B 跑完。依赖约束（char09-04）优先于并行优化，这是多 Agent 调度的铁律。

最后记住线程 vs 进程的选择原则：IO 密集用 threading，CPU 密集用 multiprocessing——网络请求、sleep、文件读写都是 IO 密集，计算密集（如图像处理、大量数据遍历）才需要多进程。

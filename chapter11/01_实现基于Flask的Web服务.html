例 11-1 讲解：基于 Flask 的 A2A Agent Web 服务

本节核心变化：char10 全部在 Python 进程内用"函数调用"模拟 Agent 通信。char11 是部署到真实 Web 服务——Flask 提供 HTTP 端点，外部（APP/网站/其他 Agent）通过 HTTP POST 调用。同时加入 A2A Agent Card 端点（/.well-known/agent.json），和 char10 的协议体系衔接。

一、本节要解决什么问题

char01-10 都在"造轮子"和"理解协议"——Agent 跑在 Python 脚本里，靠 main 入口直接调用。但真实生产环境里，Agent 必须部署成 可被外部调用的 Web 服务。这一篇就是迈出这一步。

教材原版的问题：

  • DashScope 用 requests.post("api/v1/services/aigc/text-generation/generation")——这个 v1 端点已经下线，标准做法是用 dashscope SDK
  • API Key 变量名 QWEN_API_KEY 混乱（实际指向 DashScope）
  • status_code == 200 粗糙判断，没有 try/except（网络超时、DNS 错误、502 上游错误）
  • 没有 A2A Agent Card 端点（和 char10 的协议脱节）
  • 没有健康检查端点（生产部署必需）
  • 没有 main self-test（只能 Flask run，无法自动验证）

二、改写后的 Flask 应用 4 个端点

GET /well-known/agent.json

A2A Agent Card 发现端点（char10 协议规范路径）。Agent 把自己的身份、endpoint、skills 宣告出去。其他 Agent 发现端点后就能知道"这个 Flask 服务能干什么"。

GET /health

健康检查端点。K8s / Docker / 负载均衡器用这个端点判断"服务还活着吗"。返回 status + timestamp + version + 支持的模型列表。

POST /ask

核心业务路由。接收 question + model 参数，调用 DashScope qwen-plus 或 DeepSeek Chat，返回 answer + model + elapsed_ms + timestamp。完整错误处理（400 参数错误 / 400 API Key 缺失 / 502 上游错误 / 500 内部错误）。

GET /error handler

Flask 错误处理器（404 / 405）。返回 JSON 格式错误，比 Flask 默认的 HTML 错误页更适合 API 消费方。

四、完整请求处理流程（/ask 端点）

1JSON 解析（force=True + silent=False 让 Flask 抛异常）
  失败 → 400 Invalid JSON
2参数校验（question 非空？model ∈ {qwen, deepseek}？）
  失败 → 400 参数错误
3模型分发（if model=="qwen" → call_dashscope；else → call_deepseek）
4try/except 三层：ValueError → 400 | requests.RequestException → 502 | Exception → 500
5返回 JSON（answer + model + elapsed_ms + timestamp）

完整请求示例（用 curl 调用）

# 健康检查
curl http://localhost:5000/health
# → {"status":"ok","version":"1.0.0","models":["qwen-plus","deepseek-chat"],...}

# Agent Card
curl http://localhost:5000/well-known/agent.json
# → {"name":"flask-chat-agent","skills":[...],"authentication":{"schemes":["bearer"]},...}

# 问答（DashScope）
curl -X POST http://localhost:5000/ask \
  -H "Content-Type: application/json" \
  -d '{"question":"1+1=?","model":"qwen"}'
# → {"answer":"2","model":"qwen-plus","elapsed_ms":801,...}

# 问答（DeepSeek）
curl -X POST http://localhost:5000/ask \
  -H "Content-Type: application/json" \
  -d '{"question":"什么是A2A协议","model":"deepseek"}'

七、与 char10 A2A 协议的衔接

这个 Flask 服务就是 char10 A2A Agent 的 HTTP 部署！

char10 的所有 A2AServer/A2AClient 都是 Python 进程内的对象。这一篇把它们暴露成真正的 HTTP 端点：

char10 概念char11 实现
Agent Card（身份+skills）GET /well-known/agent.json
A2AServer.message_send()POST /ask
A2AServer.verify_auth()可扩展：检查 Authorization Bearer header（当前示例保留可选）
DashScope 调用（Generation.call）call_dashscope() 函数（完全复用）

八、动手练习

  1. 加 Bearer Token 认证：在 /ask 端点开头检查 request.headers.get("Authorization")，和 char10-02 的 verify_auth() 逻辑对齐。
  2. 加 A2A JSON-RPC 格式端点：新增 POST /a2a 端点，接收 {"jsonrpc":"2.0","id":"...","method":"message.send","params":{...}} 格式的请求（和 char10 完全对齐）。
  3. 加 CORS 支持：pip install flask-cors，让浏览器端 APP 也能跨域调用这个服务。
  4. 换 production WSGI 服务器：把 Flask 开发服务器换成 waitress / gunicorn，实现里已有警告 "Do not use in production"。
  5. 加请求日志中间件：记录每次请求的 question 长度、模型选择、elapsed_ms，方便监控。

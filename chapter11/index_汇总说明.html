一、char11 的核心命题

理解了协议（char10）之后，怎么把 Agent 部署成真实可调用的 Web 服务？

char01-10 全部在 Python main 里直接调用进程内对象（agent.call()）。char11 迈出部署的第一步：Flask HTTP 端点把 A2A Agent 暴露出去，让外部 APP、网站、其他 Agent 都能通过 HTTP POST 调用。

二、Flask 服务 4 个端点

GET /well-known/agent.json A2A Agent Card 标准发现路径，宣告自己的身份 + skills + auth 方案 A2A 规范
GET /health 健康检查，K8s/Docker/负载均衡器判断服务是否活着 生产必需
POST /ask {question, model} 核心业务端点，DashScope qwen-plus / DeepSeek Chat 双后端可选 self-test 覆盖
GET 404 / 405 error handler 统一 JSON 错误格式，替代 Flask 默认 HTML 错误页 覆盖全部错误

三、双 LLM 后端架构

DashScope qwen-plus（SDK 模式）

  • 调用：dashscope.Generation.call() —— SDK 封装
  • API Key：DASHSCOPE_API_KEY（前 10 章统一）
  • 错误处理：SDK 抛 Exception → ask() 统一 except → 500
  • 和 char10 复用：完全相同的调用模式
  • self-test：✅ 真实 API 调用通过（answer=2, elapsed=801ms）

DeepSeek deepseek-chat（HTTP 模式）

  • 调用：requests.post() —— HTTP 直调
  • API Key：DEEPSEEK_API_KEY（独立变量）
  • 错误处理：requests.RequestException → 502 上游错误
  • 和 char10 复用：char11 首次引入
  • self-test：❌ 不硬调（无 Key 会失败）

扩展第三个模型成本极低：加一个 call_xxx() 函数 + /ask 里加一个 elif 分支。Flask 的 model 分发就是经典的"策略模式"。

八、生产级扩展方向

CORS + 真实认证

  • pip install flask-cors —— 浏览器端跨域
  • /ask 开头加 Bearer 检查（verify_auth，和 char10-02 对齐）
  • Agent Card authentication 声明 bearer 后其他 Agent 会自动加 token

WSGI + 异步队列

  • waitress（Windows）或 gunicorn（Linux）替换 Flask dev server
  • Celery / RQ 把 LLM 调用下沉异步队列，Flask 只做参数校验
  • /ask 立即返回 task_id，后台处理完调 SSE 推送

A2A 完整 JSON-RPC 端点

  • 新增 POST /a2a，接收 {"jsonrpc":"2.0","id":"...","method":"message.send","params":{...}}
  • 复用 char10 build_request/build_response/build_error_response
  • 外部 A2A Client 能直接发现并调用

容器化部署

  • Dockerfile 暴露 PORT 5000
  • docker-compose.yml 绑定 DASHSCOPE_API_KEY 环境变量
  • /health 作为 K8s readiness probe

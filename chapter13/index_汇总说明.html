一、这 11 个 py 文件想表达什么

一句话回答：这 11 篇代码合起来是一个可以真实运行的复合智能体系统——从 AI 大模型开发架构的角度看， 它们完整覆盖了「接口层 → 入口层 → 能力层 → 协议层 → 主控层 → 测试层」六层骨架， 每篇补齐一块拼图；同时每篇都经历「教材简化版 → 生产级改写 → 5 项 self-test 实测通过」的完整工程化过程， 因此它们同时表达了两件事：一个智能体系统长什么样，以及把玩具代码变成生产代码要修哪些东西。

从大模型开发的技术演进视角，11 篇实际上回答了智能体开发的五个核心问题：

核心问题对应篇章给出的答案

三条架构主线

主线一：实现层的分层构建（01 → 08）

01 接口地基（数据结构）→ 02 入口（安全）→ 03 能力（工具）→ 04 秩序（状态）→ 05 知识（RAG）→ 06/07 协议（MCP/A2A 真实标准）→ 08 总控（把 03 的工具循环、05 的知识、01 的结构整合成 AgentCore）。 阅读顺序必须自底向上：08 的一切机制（工具循环、回退、记忆、steps）都在 03/04/05 里先以最小形态出现过。

主线二：协议标准的「借壳 → 真规范」（06 / 07）

教材的「MCPMessage」「A2AMessage」只是给自造结构起了行业协议的名字（借壳），与真实协议毫无关系。 改写按真实 MCP 2025-06-18（JSON-RPC 2.0 信封 + initialize 生命周期 + tools 原语）与 真实 A2A Google 2025（AgentCard + message/send + Task 生命周期）重构，并在每篇文档中给出 「教材简化版 vs 真实规范」的维度对照——新人必须知道：叫 MCP 的代码不一定是 MCP。

主线三：测试层的三步质量闭环（09 → 10 → 11）

09 测能力（工具调对了吗——消费 08 的 steps 轨迹）→ 10 测负载（并发下稳不稳、会话隔离吗）→ 11 测内容（回答符合事实吗——LLM-as-a-Judge）。三者构成「功能正确 → 能力可信 → 负载可靠 → 内容可信」的完整质量链， 且 09/10/11 全部消费 08 建立的结构化契约——可观测性设计是测试框架的前提。

四、贯穿全章的不变式

以下六条在 11 篇中全部成立（详见 SVG-4 不变式规律），是本章真正的「架构资产」：

#不变式内容与依据
1dashscope 统一调用Generation.call + result_format="message"，全章零 LangChain 中转；tools 参数必须 {"type":"function","function":{...}} 外层包装（裸列表被静默忽略——实测教训）
2LLM 输出永不执行三步 JSON 清洗（02/11）+ AST 白名单 safe_eval（03）；LLM 输出永远是数据不是代码
3错误与状态都是数据双层失败语义（工具错误回填 / 模型级回退）；布尔 success；None≠False；杜绝 "[ERROR]" 字符串混流
4注册表消灭 if/elifMODEL_REGISTRY / TOOL_IMPLS / TASK_REGISTRY / INTENT_ROUTES / STATUS_TRANSITIONS——新增能力 = 注册一行，不改控制流
5可观测性内建run 返回 {"success","reply","steps"}；attempted_slots 回退留痕；metrics 结构化——verbose 布尔开关出局
6self-test 分层验证确定性单测 + 真实链路冒烟 + LLM 非确定行为分路径验契约；11 篇 × 5 项全部实测通过

五、教材通病与改写范式

11 篇教材原代码呈现出高度一致的通病模式，识别它们本身就是重要的学习内容：

教材通病出现篇目改写范式
虚构类 + 过时 import（Qwen2Chat / DeepSeekChat / langchain.schema）全部 11 篇（import 即崩）dashscope 原生协议统一替换
legacy 全家桶（initialize_agent / AgentExecutor / Tool.from_function 双重包装）03 / 08 / 09 / 10手写最小工具循环（看得见 mechanics）
协议借壳（MCP / A2A 徒有其名）06 / 07按真实官方规范重构 + 对照表辨析
错误字符串混流（"[ERROR] ..." 返回值）02 / 03 / 08 / 09 / 10 / 11结构化契约（布尔 success / None 语义 / 字段化错误）
回退形同虚设（裸实例传 executor，回退代码与执行路径脱节）08 / 10 教材版回退内嵌在每一轮模型调用层 + attempted_slots 留痕验证
测试逻辑本身是坏的（用内部工具名匹配自然语言回复；用字符相似度冒充事实校验；用随机数冒充用户评分）09 / 11结构化轨迹比对 + LLM-as-a-Judge + 实测对照证明教材算法方向相反
无 self-test + import 即执行全部 11 篇5 项 self-test + main 入口保护（--demo 演示）

六、新人学习路径建议

第一周：读懂骨架（按依赖顺序，不按编号跳读）

  1. 先看 SVG-1 分层总图 与 SVG-2 演进线 建立全局；
  2. 读 01（数据结构）→ 03（工具循环与双层失败语义，全章最核心的机制篇）→ 08（主控如何整合）；
  3. 每篇先读 py 文件头部注释（教材问题清单 + 改写说明），再读代码，最后跑一遍看 self-test 输出。

第二周：横向扫描不变式与协议

  1. 对照 SVG-4，在 11 篇里各找出不变式的代码落点（如 TOOL_IMPLS 在 03/08、_clean_json 在 02/11）；
  2. 精读 06/07 的「教材简化版 vs 真实规范」对照——理解 MCP 与 A2A 的真实分工：MCP 管「Agent 接工具」，A2A 管「Agent 接 Agent」；
  3. 读 05 理解 RAG 三段流水线与 cache.json 缓存的成本意义。

第三周：测试视角与动手改造

  1. 从 09/10/11 反过来看 08：为什么 steps / 结构化契约是测试的前提；
  2. 动手练习：给 03 加一个新工具并注册（体验注册表扩展）、给 09 加测试用例、复现 10 练习 2 的并发串话；
  3. 每篇 HTML 讲解文档末尾都有「动手练习」区，按由浅入深完成。

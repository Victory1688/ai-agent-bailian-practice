一、教材原版问题诊断

教材原代码声称实现了「幻觉率 + 用户满意度评估」，逐行核查后发现八个问题（原代码已全部注释保留在 py 文件头部，编号对应）：

编号问题后果与辨析
①虚构类 + 过时 importQwen2Chat / DeepSeekChat 虚构类 + langchain.schema 过时 import（13-08/09/10 同款）——import 即崩，从未跑通过。
②【最严重】字符相似度冒充幻觉检测difflib.SequenceMatcher.ratio() < 0.6 判幻觉——字符相似度与事实一致性是两个维度：事实正确但表述不同的回答相似度可能低于阈值（误判）；编造数值的回答因大部分字符相同反而相似度高（漏判）。测出来的幻觉率方向都可能是反的。
③满意度是纯随机数random.randint(3, 5) 打分——评分与回答内容毫无关系，统计出的「平均满意度」没有任何意义。
④"[ERROR]" 字符串混流错误返回字符串 + user_score 靠 "[ERROR]" in generated 字符串包含判错（13-10 已确立的反模式）。
⑤阈值 0.6 无依据拍脑袋值；SequenceMatcher 对中英混排、标点差异极敏感，同一事实换个标点相似度就大变。
⑥import 即执行run_demo() 写在模块顶层，无入口保护。
⑦无失败隔离某条模型调用失败不会计入统计口径（error 字符串会被当回答参与相似度计算）。
⑧无 self-test零验证——②③两个根本性错误因此从未被发现。
本篇核心教学点——「测什么」与「用什么测」必须匹配：幻觉检测的对象是事实一致性（语义维度）， 而 difflib 测的是字面重叠（形式维度）。用形式指标冒充语义判断，是评估系统设计中最隐蔽也最致命的错误—— 它能跑、能出数、甚至数字看起来很稳定，但数字的含义是错的。这也是真实业界转向 LLM-as-a-Judge 的根本原因： 语义判断只能由具备语义理解能力的评估者（裁判模型）来做。

二、改写后总览（LLM-as-a-Judge）

LLM-as-a-Judge 是 2024-2025 业界 LLM 评估的主流路线（Ragas、DeepEval、OpenAI evals 均是此路线）： 用一个（更强的）模型当裁判，按明确的判定标准对被测模型的输出做结构化评判。

整体执行流程

EVAL_SET（教材 5 条 QA 原样保留：question + reference）
  ──→ 对每条：
      ──→ 被测模型（qwen-plus）生成回答
      ──→ 裁判模型（qwen-plus）判定：
          faithful（事实一致？表述不同不影响）/ score（1~5 内容评分）/ reason
      ──→ 裁判输出 → _clean_json 三步安全清洗（剥围栏→括号定位→严格解析）
      ──→ difflib 相似度（辅助指标，单独报告，与事实判定分开）
  ──→ 汇总 metrics：幻觉率 / 平均满意度 / 平均相似度 / 裁判失败数 / 逐条详情

两个模型各司其职

角色模型职责
被测模型qwen-plus对评估问题生成回答——它是「考生」，其回答质量是被测对象
裁判模型qwen-plus（生产建议更强模型）按 faithfulness 标准判定事实一致性 + 给内容评分——它是「考官」，输出结构化 JSON
「裁判也是 qwen-plus，自己给自己判」的说明：教学场景下为控制成本与依赖复杂度，裁判复用同一模型。 真实生产中裁判应选更强或至少不同家族的模型（如 qwen-max、或第三方模型）以降低「自我偏好」偏差； 评估框架本身（JUDGE_MODEL 常量）已预留切换点，改一行即可换裁判。

三、核心组件详解（1）裁判 prompt 与输出清洗

3.1 JUDGE_PROMPT：判定标准显式化

JUDGE_PROMPT = """你是严格的事实性评估裁判。给定【问题】【模型回答】【参考答案】，请判定：
1. faithful：模型回答的核心事实是否与参考答案一致。判定标准：
   - 关键事实（数值、主体、时间、名单）不矛盾即为一致，即使表述方式完全不同；
   - 回答补充了参考答案之外的正确信息，不影响一致性判定；
   - 关键事实错误、编造、或与参考答案冲突，判为不一致。
2. score：作为用户对该回答的满意度评分（1~5 整数）：
   1=答非所问或关键事实错误；3=基本正确但不完整；5=准确完整且表述清晰。
只输出一个 JSON 对象，不要输出任何其他内容：
{"faithful": true或false, "score": 1到5的整数, "reason": "一句话理由"}"""

prompt 的三个设计要点：

  1. 正例与反例边界都写明：「表述方式完全不同不影响判定」直接封死教材 difflib 的误判路径；「补充正确信息不影响」避免裁判把完整性问题混淆为事实问题；
  2. score 的分档语义明确（1/3/5 锚点），减少裁判打分的随机漂移；
  3. 只输出 JSON——结构化输出是下游可解析的前提，配合下面的安全清洗。

3.2 _clean_json：三步安全清洗（13-02 确立模式）

def _clean_json(text: str) -> dict:
    cleaned = text.strip()
    # 第一步：剥 ```json 围栏（若存在）
    if cleaned.startswith("```"):
        cleaned = cleaned.strip("`")
        if cleaned.startswith("json"):
            cleaned = cleaned[4:]
    # 第二步：定位首尾大括号（截掉前后缀文本）
    start, end = cleaned.find("{"), cleaned.rfind("}")
    if start == -1 or end == -1 or end <= start:
        raise ValueError(f"裁判输出中未找到 JSON：{text[:80]}")
    # 第三步：严格 json.loads（不 eval，杜绝代码执行）
    return json.loads(cleaned[start:end + 1])
为什么必须清洗：裁判模型即使被要求「只输出 JSON」，实测仍可能输出 ```json 围栏 或 「评估结果如下：{...} 以上。」这类前后缀。三步清洗（剥围栏 → 括号定位 → 严格 json.loads）与 13-02 意图识别入口 的清洗逻辑同源——LLM 输出永远当数据不当代码（不用 eval），且永远做结构容错（三种输出形态都接得住）。 Test 1 对这三种形态做了确定性单测。

3.3 judge_answer：None 与 False 的语义区分

return {"faithful": bool(verdict.get("faithful")),
        "score": int(verdict.get("score", 0)),
        "reason": str(verdict.get("reason", ""))}
# 裁判调用失败时：{"faithful": None, "score": None, "reason": "失败说明"}

None ≠ False：False 是「裁判判定为不一致」，None 是「裁判没判成」（网络失败/输出不合法）。 两者在统计口径上严格分开——幻觉率只按裁判成功的条目计算，失败条目单独计数（judge_failures 字段）， 避免把「评估基础设施故障」算进「被测模型的幻觉」。

四、核心组件详解（2）评估流水线

4.1 evaluate_case：单条评估的三步

def evaluate_case(item: dict) -> dict:
    generated = generate_answer(item["question"])           # 1. 被测模型生成
    verdict = judge_answer(item["question"], generated,
                           item["reference"])               # 2. 裁判判定
    return {
        "question": item["question"],
        "generated": generated[:60],
        "reference": item["reference"],
        "faithful": verdict["faithful"],
        "score": verdict["score"],
        "reason": verdict["reason"],
        "similarity": round(text_similarity(generated, item["reference"]), 3),
    }

4.2 run_evaluation：统计口径设计

judged = [d for d in details if d["faithful"] is not None]  # 裁判成功的条目
hallucinated = sum(1 for d in judged if not d["faithful"])
metrics = {
    "total": len(details),
    "hallucinated": hallucinated,
    "halluc_rate": round(hallucinated / len(judged), 3) if judged else None,
    "avg_score": round(sum(scored) / len(scored), 3) if scored else None,
    "avg_similarity": ...,        # 辅助指标单独汇报
    "judge_failures": len(details) - len(judged),
    "details": details,
}
满意度指标的定位澄清：改写后的 score 由裁判模型基于回答内容给出（准确性/完整性/清晰度分档）， 比教材的 random.randint 至少是「内容相关的代理评分」。但必须明确：它仍是模拟评分—— 真实用户满意度应从产品埋点采集（点赞/点踩、会话留存、复访率）。 评估代码里叫「满意度」，文档里要讲清「这是内容质量代理，不是真实用户数据」——教材的毛病恰恰是把随机数直接叫「用户评分」。

五、核心组件详解（3）difflib 实证对照

改写没有删除 difflib 相似度，而是把它降级为辅助指标单独报告——并用实测数据证明「为什么它不能当幻觉检测」：

实测场景结果
qwen-plus 对 5 条教材题的回答全部事实正确（裁判判定幻觉率 0.0、均分 5.0）但 difflib 平均文本相似度仅 0.089
按教材标准（相似度 < 0.6 判幻觉）这 5 条全部正确的回答会被 100% 误判为幻觉——教材算法的方向完全相反
Test 3 编造用例：「地球上最大的哺乳动物是非洲象」与参考答案字符相似度约 0.72（> 阈值 0.6，教材会漏判）；裁判模型正确判为不一致、评分 1
双向失灵的完整证据链：正确的回答被误判（0.089 < 0.6）、编造的回答被漏判（0.72 > 0.6）—— 教材的幻觉检测在两个方向上都是反的。这组实测数据是本篇最有教学价值的产出： 相似度可以告诉你「两个文本长得像不像」，永远不能告诉你「两句话说的是不是同一个事实」。

九、动手练习与延伸阅读

动手练习（由浅入深）

  1. 跑通基线：执行 python 11_Test模型幻觉率与用户满意度评估.py --demo，逐条观察 faithful/score/reason/similarity——重点看「reason 一句话理由」是否说到点子上（裁判可解释性）。
  2. 复现教材误判：对 5 条 EVAL_SET 手动算一遍 difflib 相似度（Test 2 的 text_similarity 现成可用），对照阈值 0.6——亲眼确认「全对却被判全幻觉」。
  3. 加难度题：在 EVAL_SET 里加 2 条时效性题（如「截至2025年X事件的最新进展」）与 1 条陷阱题（问题隐含错误前提），观察幻觉率是否从 0 开始上升——体会「评估集难度决定结论强度」。
  4. 换裁判：把 JUDGE_MODEL 改为 qwen-max（若账号可用），对比同一组回答两裁判的判定是否一致——引出「裁判间一致性（judge agreement）」概念。
  5. 进阶：把裁判 prompt 的 score 改为多维输出（准确性/完整性/清晰度各 1~5 分），观察维度分解后能暴露哪些单分数掩盖的问题（如事实全对但表述混乱）。

例13-5 RAG 检索问答子系统（char13-05）

第13章 项目案例：从零实现一个复合智能体系统 ｜ 改写基准：dashscope text-embedding-v3 + 轻量 RAG 流水线 ｜ 状态：已实测验证（5 项 self-test 全部通过）

复合智能体需要"开卷考试"的能力：模型参数里没有的企业知识、实时信息，要靠检索增强生成（RAG）——先从知识库检索相关片段，再让模型基于片段回答。教材版用一串已废弃的 LangChain 组件（ConversationalRetrievalChain + ConversationBufferMemory + Chroma + 本地 HuggingFace 模型）搭了一个跑不起来的黑盒；改写版把手拆开，检索 → 增强 → 生成三段流水线全部显式化，顺便解决了重复计费、错误混流、多轮记忆三个实际问题。

二、改写后总览：显式化的三段流水线

构建期（一次）：KNOWLEDGE_TEXT → split_text 分块（6 片段）→ EmbeddingClient 向量化
｜　　（向量落盘 cache.json，md5 键——重复运行零二次计费）
问答期（每次）：用户问题 → KnowledgeBase.search（余弦相似度 top-2）
↓ 片段拼装进 RAG_PROMPT_TEMPLATE（增强）
↓ 对话历史 self.history 注入 messages（多轮记忆）
↓ 主模型 qwen-plus → 失败备用 qwen-turbo（生成）
↓ 返回结构化契约 {"success", "answer", "sources"}

教材的业务语义全部保留：k=2 检索、多轮对话、qwen/deepseek 双模型切换、三个测试问题。变化在于每个环节都显式、可测、可溯源。

三、核心组件 1：EmbeddingClient —— 云端嵌入 + 可证明的缓存

用 dashscope text-embedding-v3 替代本地 HuggingFace 模型，核心设计是缓存命中直接返回，未命中才调 API 并落盘：

def embed(self, texts: list) -> list:
    result = [None] * len(texts)
    misses = []   # [(索引, 文本)] 缓存未命中的条目
    for i, t in enumerate(texts):
        cached = self.cache.get(self._key(t))   # md5(text) → 向量
        if cached is not None:
            result[i] = cached
        else:
            misses.append((i, t))
    for start in range(0, len(misses), EMBED_BATCH):   # 每批不超过 10 条
        batch = misses[start:start + EMBED_BATCH]
        resp = dashscope.TextEmbedding.call(
            model=EMBEDDING_MODEL, input=[t for _, t in batch], dimension=1024)
        if resp.status_code != 200:
            raise RuntimeError(f"{resp.code} {resp.message}")
        self.api_calls += 1                            # 调用计数（测试用）
        for (idx, t), item in zip(batch, resp.output["embeddings"]):
            result[idx] = item["embedding"]
            self.cache.set(self._key(t), result[idx])   # 落盘，下次零计费
    return result
为什么缓存值得做，且值得"可证明"：嵌入 API 按量计费，知识库不变时向量永不变化——重复运行、重复构建、重复提问都在白花钱。更有意思的是 api_calls 计数器：self-test 里二次构建断言 api_calls == 0，把"缓存生效"从一句口头承诺变成可运行的证明（Test 2 实测通过）。这与 attempted_slots 验证回退是同一个方法论：关键机制要留下可断言的痕迹。

class KnowledgeBase:
    def search(self, query: str, k: int = TOP_K) -> list:
        q_vec = self.embedder.embed([query])[0]
        scored = [(self.embedder.cosine(q_vec, v), chunk)
                  for chunk, v in zip(self.chunks, self.vectors)]
        scored.sort(key=lambda x: x[0], reverse=True)
        return [chunk for _, chunk in scored[:k]]
  • 分块：内置知识库段落短，按段落切即可；超长段落才滑窗兜底——保留教材 CharacterTextSplitter 的切分语义，粒度更合理；
  • 检索：问题的向量与全部块向量算余弦相似度，取 top-k——这就是向量检索的全部数学本质，40 行替代一个向量数据库依赖；
  • 语义命中实测："什么是Transformer架构？"的 top-1 精确命中 Transformer 段落（问题里没有一个词与片段完全相同，靠的是语义而非关键词）。
教学取舍说明：纯 Python 余弦检索在万级片段内完全够用；生产到十万/百万级才需要 FAISS/Milvus 等专用索引。先理解数学本质，再上工程工具——这是本课程一贯的学习路径。

五、核心组件 3：RAGAgent —— 多轮记忆与结构化返回

def ask(self, query: str) -> dict:
    try:
        sources = self.kb.search(query)                       # ① 检索
        context = "\n".join(f"- {s}" for s in sources)
        prompt = (RAG_PROMPT_TEMPLATE
                  .replace("{context}", context)
                  .replace("{query}", query))                 # ② 增强
        messages = self.history + [{"role": "user", "content": prompt}]
        answer = None
        for slot in ("primary", "backup"):                    # ③ 生成（主备回退）
            self.attempted_slots.append(slot)
            try:
                answer = self._invoke(MODEL_REGISTRY[slot]["model"], messages)
                break
            except Exception as e:
                logger.warning(f"[回退] {slot} 模型级失败: {e}")
        ...
        self.history.append({"role": "user", "content": prompt})
        self.history.append({"role": "assistant", "content": answer})
        return {"success": True, "answer": answer, "sources": sources}
    except Exception as e:
        return {"success": False, "answer": "", "sources": [], "error": str(e)}
教材问题改写方案
每次 ask 重建 ConversationalRetrievalChainRAGAgent 装配一次全程复用，ask 只做流水线三步
ConversationBufferMemory（已废弃）管记忆self.history 原生 messages 列表，每轮问答后追加——多轮记忆就是"把历史放进 messages"这么直接
错误字符串混在回答里结构化契约 {"success", "answer", "sources"}，失败走 success=False + error 字段，调用方可程序化分支
回答不带检索来源sources 字段返回引用片段，回答可溯源
模板填充replace 填充（13-02 format 花括号坑的系列惯例）
一个值得注意的细节：历史里存的是增强后的完整 prompt（含检索片段），不只是用户原话。这样模型下一轮能看到"上一轮我依据哪些片段回答的"，指代消解更稳——实测第二轮"那它和机器学习是什么关系？"正确接上"深度学习"（Test 4 验证）。代价是历史增长更快，生产中需配合窗口截断（char08-05 的裁剪策略）。

Test场景结果

九、动手练习与延伸阅读

练习 1：相似度阈值过滤

给 search() 加 min_score 参数：低于阈值的片段不返回。然后问一个知识库里没有的问题（如"量子计算机的原理"），观察模型在"片段不足"时的表现——对比有无阈值时回答质量的变化。

练习 2：接入 13-04 调度器

把 RAGAgent 包装成 TASK_REGISTRY 里的 knowledge 子 Agent（提示词模板直接透传问题），验证"加一行注册、零改动控制器"的扩展方式——让复合智能体具备知识问答能力。

练习 3：历史窗口裁剪

self.history 目前无限增长。参照 char08-05，给 RAGAgent 加 max_history_rounds，超过时裁掉最早的轮次——思考为什么历史裁剪不会影响检索质量（提示：检索上下文每轮重新获取）。

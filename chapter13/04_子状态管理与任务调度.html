例13-4 子状态管理与任务调度（char13-04）

第13章 项目案例：从零实现一个复合智能体系统 ｜ 改写基准：dashscope 原生协议 + 显式状态机 ｜ 状态：已实测验证（5 项 self-test 全部通过）

复合智能体不是一个大模型包打天下，而是按任务类型拆成多个子 Agent（意图识别 / 问答 / 工具调用 / 对话），由调度器统一派发。既然有"子系统"，就有两个新问题：每个子 Agent 的状态怎么管（空转 / 运行中 / 成功 / 失败），任务怎么调度（派给谁、失败怎么办）。教材版给了状态字段和调度骨架，但状态机是纸糊的（随便跳）、调度映射是散弹式的（两处平行维护）——本篇讲解怎么把这两件事做实。

三、核心组件 1：AgentState —— 把状态机从"字段"做成"机器"

教材的状态只有四个字段没有规则。改写用两张白名单把规则写死：

VALID_STATUSES = ("idle", "running", "success", "failed")
# 迁移白名单：success/failed → running 意味着允许重新派发 / 重试
STATUS_TRANSITIONS = {
    "idle": {"running"},
    "running": {"success", "failed"},
    "success": {"running"},
    "failed": {"running"},
}

def update(self, status: str, result=None, error=None):
    if status not in VALID_STATUSES:
        raise ValueError(f"{self.name} 非法状态值：{status}（合法值 {VALID_STATUSES}）")
    if status not in STATUS_TRANSITIONS[self.status]:
        raise ValueError(f"{self.name} 非法状态迁移：{self.status} → {status}")
    self.status = status
    self.last_result = result
    self.last_error = error
  • 非法状态值拒绝：想造出 "paused" 这种野生状态？ValueError 立刻拦下；
  • 非法迁移拒绝：idle → success 的跳步（没跑就"成功"）不可能发生；
  • 重派显式建模：success/failed → running 是白名单内的合法路径——重试不是"把状态改回去"，而是一次新的合法迁移；
  • fail fast：坏状态在写入瞬间报错，而不是等到快照/下游才发现（与 13-01 Message 构造校验同一原则）。
为什么值得较真：状态机bug 的特点是"静默发酵"——idle 直接跳 success 当下看不出问题，直到某天调度器依据"成功过"做决策才炸。对照 char05 的教训（LangGraph State 用裸 dict 定义导致字段静默裁剪），状态容器必须有显式约束，这是贯穿本课程的一条不变式。

四、核心组件 2：TASK_REGISTRY —— 单一注册表消灭平行映射

TASK_REGISTRY = {
    "intent": {"name": "意图识别Agent", "prompt": "请识别该用户输入的意图：{input}"},
    "qa":     {"name": "问答Agent",     "prompt": "请回答该问题：{input}"},
    "tool":   {"name": "工具调用Agent", "prompt": "是否需要调用工具来完成该任务？{input}"},
    "dialog": {"name": "对话Agent",     "prompt": "请以自然语言与用户继续交谈：{input}"},
}

# 控制器初始化：状态单元直接从注册表生成（同键对应，不再手工抄写）
self.agents = {task: AgentState(spec["name"]) for task, spec in TASK_REGISTRY.items()}
教材做法改写做法
agents 字典（状态）+ if/elif 链（提示词）两处平行维护TASK_REGISTRY 一处定义，状态单元由注册表派生
新增子 Agent 要改两处，漏一处就是"有状态没行为"或"有行为没状态"新增 = 注册表加一行，状态与行为天然同步
if/elif 末尾 raise ValueError("未知任务类型") 是死代码（早被 if not agent 拦截）未注册类型统一在 TASK_REGISTRY.get() 一处判断，教材提示语义保留
模板用 f-string 现拼模板存注册表，用 replace("{input}", ...) 填充——例 13-02 实测：模板含花括号时 .format() 会把字面量误解析为占位符（KeyError）
设计原则：Single Source of Truth。同一件事（"有哪些子 Agent"）只能有一份定义。两份映射短期看是"清晰"，长期看必然漂移——散弹式修改是维护成本膨胀的头号来源。

五、核心组件 3：AgentController —— 异常链回退 + 完整快照

def _execute_with_fallback(self, prompt: str) -> str:
    last_err = None
    for slot in ("primary", "backup"):
        self.attempted_slots.append(slot)          # 记录尝试路径（self-test 验证回退用）
        try:
            logger.info(f"[模型] 使用 {slot}({MODEL_REGISTRY[slot]['model']}) 执行")
            return self._run_model(MODEL_REGISTRY[slot]["model"], prompt)
        except Exception as e:
            last_err = e
            logger.warning(f"[回退] {slot} 模型级失败: {e}")
    # 教材抛 RuntimeError 但不带原因；改写携带原始异常链便于排查
    raise RuntimeError(f"所有模型均执行失败，最后错误：{last_err}") from last_err
  • 教材的 try/raise 噪音删除：_run_model 不再表演容错，只负责调用与把非 200 转成 RuntimeError，兜底集中在 _execute_with_fallback；
  • raise ... from e 异常链：最终错误携带原始原因（traceback 里能看到"由什么引起"），对照教材裸抛 RuntimeError("所有模型均执行失败") 的信息黑洞；
  • 快照补全：to_dict() 输出 name / status / last_result（截断 80 字符）/ last_error 四字段——失败排查不再两眼一抹黑；
  • attempted_slots 记录：延续了 13-03 的方法论——"回退机制存在"要变成"回退机制可证明"。

九、动手练习与延伸阅读

练习 1：状态历史留痕

给 AgentState 加 history: list，每次 update 追加 {"from": 旧状态, "to": 新状态, "at": 时间戳}，并让 to_dict() 输出最近 3 条。思考：如果并发派发，history 需要什么保护？（提示：char09 的 Lock）

练习 2：失败重试上限

当前 failed → running 可以无限重试。给 AgentState 加 retry_count，failed 后再迁移到 running 时若超过 3 次则拒绝（ValueError），让调度器能识别"该放弃的任务"。

练习 3：注册表驱动的新 Agent

往 TASK_REGISTRY 加一个 translate 子 Agent（提示词："请将以下内容翻译为英文：{input}"），体验"加一行注册、零改动控制器"的扩展方式——然后回忆教材版要改几处。

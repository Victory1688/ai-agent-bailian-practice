例13-7 A2A 消息协议的模块注入（char13-07）

第13章 项目案例：从零实现一个复合智能体系统 ｜ 改写基准：真实 A2A 规范（Google 2025 发布，Agent-to-Agent Protocol）｜ 状态：已实测验证（5 项 self-test 全部通过）

复合智能体最终形态是多 Agent 协作：主 Agent 把任务交给专门的子 Agent（工具代理 / 问答代理），各 Agent 之间用标准协议通信。教材版自造了一个 A2AMessage 四字段结构就自称 A2A——但真实 A2A（Google 2025 年发布，现为 Linux 基金会托管项目）的核心是 Agent Card 自描述 + JSON-RPC 2.0 + Task 任务生命周期。本篇按真实规范重写：每个 Agent 成为一个可被发现、可跟踪任务状态的标准端点，"模块注入"升级为"能力发现 + 协议化派发"。

一、教材原版问题

编号问题后果
①"A2A"是借壳命名自造 sender/receiver/payload/metadata 四字段 ≠ 真实协议。学生以为见过 A2A，实际 Agent Card、Task、JSON-RPC 一个都没见过——同 13-06 的 MCP 借壳，是教材协议篇最需要警惕的伤害模式
②虚构类 Qwen2Chat/DeepSeekChat + 过时 import同 13-01：import 即崩
③default_handler 死代码定义了"LLM 兜底回应"却从未 register_handler 注册——永远不会被调用；而 receive_message 对未注册类型返回"不支持的任务类型"字符串，兜底与报错自相矛盾
④无任务抽象handler 返回裸字符串——成功还是失败？任务进行到哪了？结果在哪？全部无法回答，多 Agent 协作无从跟踪
⑤无能力发现调用方必须预先硬编码 receiver 的 agent 名字——真实 A2A 的核心价值恰是 Agent Card 自描述 + skill 标签匹配，"谁有什么能力"应该是可查询的

⑦metadata 无结构约束task_type / tool 全是魔法字符串，没有 schema，拼错静默失效
⑧无 self-test协议行为正确性不可验证

三、改写后总览：协议化的协作链路

模块注入：A2ARouter.register_agent(ToolAgent / AnswerAgent)（教材语义保留）
能力发现：get_agent_card 读卡片；find_agent("qa") 按 skill 标签找到 AnswerAgent

派发：A2AMessage（payload + metadata）→ 规范化 role + parts（TextPart + DataPart）
↓ JSON-RPC message/send → 目标 A2AServer.handle()
↓ 创建 Task（state=working）→ 技能执行
｜　├─ 成功 → state=completed + artifacts（TextPart 结果）
｜　└─ 异常 → state=failed + status.message（任务级失败，非协议错误）
↓ 结构化契约 {"success", "taskId", "state", "response"}

教材的业务语义全部保留：ToolAgent 模拟执行（"已调用工具：DataAnalyzer"原文）、AnswerAgent qwen-plus 问答、MainAgent 两条消息的 demo 场景。变化在于协作发生在标准协议之上。

四、核心组件 1：AgentCard 与能力发现

class AgentCard:
    """对应真实 A2A 的 /.well-known/agent.json"""
    def as_dict(self) -> dict:
        return {"name": self.name, "description": self.description,
                "url": self.url, "version": self.version,
                "protocolVersion": A2A_PROTOCOL_VERSION, "skills": self.skills}

# 网关端：按 skill 标签发现目标（替代硬编码 receiver 字符串）
def find_agent(self, skill_tag: str):
    for name, agent in self.agents.items():
        if any(skill_tag in s["tags"] for s in agent.card.skills):
            return name
    return None
  • 自描述：卡片是 Agent 的"简历"——name、职责一句话、版本、协议版本、skills（每个 skill 有 id/名称/描述/标签）；
  • 标签匹配：find_agent("qa") → AnswerAgent，find_agent("tool") → ToolAgent（Test 1 实测）——调用方从"我知道你叫什么"升级为"我知道谁能干什么"，新增 Agent 无需改动调用方代码；
  • 教学边界：生产中卡片经 GET /.well-known/agent.json 获取（跨进程）；本篇进程内直取，传输层解耦。

五、核心组件 2：A2AServer —— Task 生命周期

def _message_send(self, params: dict) -> dict:
    message = params.get("message")
    if not isinstance(message, dict) or not message.get("parts"):
        raise JsonRpcError(INVALID_PARAMS, "message.parts 不能为空")
    task_id = params.get("taskId") or message.get("taskId") or str(uuid.uuid4())
    payload = "".join(p["text"] for p in message["parts"] if p.get("kind") == "text")
    metadata = dict(message.get("metadata") or {})
    for p in message["parts"]:                 # DataPart 合入 metadata
        if p.get("kind") == "data":
            metadata.update(p.get("data") or {})
    task = {"id": task_id, "status": {"state": "working"}, "artifacts": []}
    self._tasks[task_id] = task
    try:
        text = str(self.execute(payload, metadata))
        task["status"] = {"state": "completed"}
        task["artifacts"] = [{"name": "response",
                              "parts": [{"kind": "text", "text": text}]}]
    except Exception as e:
        # 技能执行失败是任务级失败（业务性），不是协议错误——规范语义
        task["status"] = {"state": "failed", "message": str(e)}
    return task
教材问题Task 抽象的修正
handler 返回裸字符串，成功失败无法区分Task 状态机：working → completed / failed，程序化可判
结果与错误混在同一字符串通道结果放 artifacts，失败原因放 status.message——通道分离
任务发出后即失联TaskStore + tasks/get：按 id 随时查询状态（未知 id → -32001 TaskNotFound）
metadata 魔法字符串DataPart 承载结构化元数据（task_type/tool 有了标准容器）
default_handler 死代码LLM 兜底语义并入 AnswerAgent 的 qa 技能——兜底真实可达
两级错误的边界（与 13-06 MCP 的 isError 辨析同源）：协议坏了（方法不存在、参数不合法）→ JSON-RPC 错误码；协议没坏但事没办成（工具故障、模型 5xx）→ Task state=failed。混用两者是协议实现最常见的错误——比如把业务失败报成 -32602，调用方就无法区分"我调错了"还是"它挂了"。

六、核心组件 3：A2ARouter —— 模块注入 + 结构化派发

def dispatch(self, msg: A2AMessage) -> dict:
    server = self.agents.get(msg.receiver)
    if server is None:
        return {"success": False, "taskId": None, "state": "unknown",
                "response": "", "error": f"目标Agent不存在：{msg.receiver}"}
    self._next_id += 1
    request = {"jsonrpc": "2.0", "id": self._next_id, "method": "message/send",
               "params": {"message": msg.to_a2a_message()}}
    response = server.handle(request)
    if "error" in response:
        err = response["error"]
        return {"success": False, ..., "error": f"{err['code']} {err['message']}"}
    task = response["result"]
    state = task["status"]["state"]
    text = "".join(p["text"] for a in task.get("artifacts", [])
                   for p in a.get("parts", [])) if state == "completed" else ...
    return {"success": state == "completed", "taskId": task["id"],
            "state": state, "response": text}

register_agent 模块注入语义保留；dispatch 从"返回字符串"升级为"返回结构化契约"，未注册目标、协议错误、任务失败三条失败路径各有独立字段（修复教材错误混流）。网关本身不懂任何业务——它只搬运 JSON-RPC，这正是协议的价值：网关换掉、Agent 不用改。

四、char08 独有的三笔"学费清单"（系列最珍贵部分）

学费 1：LangChain Memory 经典陷阱——chat_memory.messages 绕开窗口截断

04 篇原代码直接用 chat_memory.messages 取历史——这是全量累积视图，k=3 参数形同虚设。窗口截断只在 load_memory_variables({})['history'] 时发生。实测对照：

错误姿势（原代码）：Round 4 时窗口视图 8 条（k 参数完全失效）
正确姿势（修复后）：Round 4 时原始存储 8 条 | 窗口视图 6 条（Round 1 被裁掉）

这是 LangChain Memory 最容易踩的坑——很多人以为 chat_memory 就是窗口化后的结果，其实它是"读时过滤"设计：存储永远全量，截断发生在读取时。

学费 2：死代码谱系第三线——注册了但从未调用
篇死代码根因
char07-03tool 路由分支子任务丢失关键词
char07-04hybrid 路由分支if/elif 顺序截胡
char08-04（本篇）FakeDataFetcher 工具注册给 Agent 但 ask() 里从未调用

教材的死代码从"路由分支"扩展到"工具注册"——FakeDataFetcher 初始化了、注册了，但 LLM 回答全靠自己的知识，工具是纯摆设。加上 04 篇的三个死 import（OpenAI/ConversationChain/messages_from_dict 导入未用），本篇是教材"模板残留"的重灾区。

学费 3：降级 prompt 的风格漂移 + LLM 质疑假数据

03 篇实测两个意外发现：

  • 降级时输出风格悄悄变了：正常路径 prompt 要求"语言简洁"，降级路径只说"简明解释"——实测降级回答更长更结构化（带分节和风险清单）。生产系统应统一两条路径的风格约束，避免用户体验跳变。
  • LLM 会质疑不可信的工具数据：工具（假数据）给 5.3%，qwen-plus 没有照单全收，主动指出"显著高于历史趋势和主流机构预期"并附可持续性警告。但这不是可靠保障——数据质量必须从源头保证，不能指望下游 LLM 兜底。

七、char08 的集大成者：一个完整请求的生命周期

用户输入 "请预测2024年美国的GDP增长趋势"
    │
    ▼ ① 能听（02 篇）
parse_input → {"region": "美国", "year": 2024, "focus": "GDP"}
    │
    ▼ ② 能记（04 篇）
load_memory_variables({})['history'] → 取最近 k=3 轮窗口视图
    │
    ▼ ③ 能省（05 篇）
dynamic_clip_context(pool, token_limit) → priority 排序 + 贪心装填
    │
    ▼ ④ 能扛（03 篇）
tool.call() → 成功走正常 prompt / 失败走降级 prompt
    │
    ▼ ⑤ 能看（01 篇）
update_state: READY→RUNNING→WAITING_TOOL→RUNNING→COMPLETED
    │
    ▼
dashscope.Generation.call(qwen-plus) → 回答 → 回写 memory → 返回用户

这就是 char08 五篇合体的完整拼图——每篇教一个环节，五篇合起来是单 Agent 的全链路。动手练习的终极任务就是把五篇代码真正合并成一个 Agent 类。

八、给新人的学习路径

① 先跑 01 → 理解状态机是什么
   自测：把 ForecastTool 改成 raise Exception，观察 FAILED 分支

② 再跑 02 → 理解 NL→结构化的翻译桥
   自测：用"明年"、"欧盟和美国"、"小写cpi"三句话复现规则盲区

③ 重点读 03 → 理解优雅降级
   自测：monkeypatch random 强制两条路径，对比输出风格差异

④ 细读 04 → 亲手复现 chat_memory bug
   自测：把 load_memory_variables 改回 chat_memory.messages，看窗口失效

⑤ 最后读 05 → 理解 Token 预算装填
   自测：token_limit 从 100 收紧到 30，观察"跳过不终止"特性

⑥ 终极综合：把五篇合并成一个 StatefulSmartAgent 类
   状态机（01）+ 解析（02）+ 降级（03）+ 记忆（04）+ 剪辑（05）
   ——这就是本课程的毕业设计
